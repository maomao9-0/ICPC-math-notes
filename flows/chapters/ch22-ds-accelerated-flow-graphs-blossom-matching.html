1. Module 22A — The Virtual Hub DAG Sparsification Principle (数据结构优化建图)

In Chapters 07 through 21, we treated the number of edges \(M\) in a compiled flow network as a linear function of the problem description. Yet in a vast class of advanced competitive programming problems, the algebraic or logical model is completely clean — a Project Selection closure (Chapter 09), a Bipartite Matching (Chapter 07), or a DAG Minimum-Cost Path Cover (Chapter 17) — except that the edge set is defined implicitly by geometric, order-theoretic, or string predicates:

  • “Selecting item \(i\) conflicts with every item \(j < i\) whose weight satisfies \(L_i \le w_j \le R_i\).” ([BZOJ 3218] a + b Problem)
  • “Weapon \(i\) can destroy any spaceship in the contiguous interval \([l_i, r_i]\).” ([CF 1045A] Last Chance)
  • “Connecting node \(i\) to an earlier node \(j < i\) as its predecessor costs \(|a_i - a_j|\).” ([SDOI2019] 通信)
  • “A rook at \((r, c)\) can attack any unblocked cell in the same row or column outside \(Q\) forbidden rectangles.” ([CF 793G] Oleg and chess)

If \(N = 5 \times 10^4\), materializing these transitions pairwise creates \(\Theta(N^2) \approx 2.5 \times 10^9\) edges, causing both Memory Limit Exceeded (MLE) and Time Limit Exceeded (TLE) long before Dinic or MCMF even starts. Data-Structure-Accelerated Graph Construction (数据结构优化建图) resolves this bottleneck not by inventing a new flow algorithm, but by algebraically factoring dense bipartite cliques \(A_k \times B_k\) through a sparse Virtual Hub DAG \(\mathcal{H}\).

1.1 The 4-Step Compilation of a Dense Biclique Family

Let us apply our 4-Step Zero Magic Gadgets protocol to the general problem of sparsifying a family of \(K\) dense transition blocks \(\{(A_k, B_k, c_k, w_k)\}_{k=1}^K\) over an original vertex set \(V\) (\(|V| = N\)).

Step 1: Non-Graph Diagnostic Signal (Recognition)

You have already reduced the problem statement to a standard flow or cut formulation over \(N \le 10^5\) original entities, but the transitions are given as \(K \le 10^5\) bulk rules where each rule \(k\) connects a structured source subset \(A_k \subseteq V\) to a structured target subset \(B_k \subseteq V\). Naive edge generation yields \(\sum_{k=1}^K |A_k|\cdot |B_k| = \Theta(N^2)\) edges, whereas each subset \(A_k\) or \(B_k\) is a 1D interval, a 2D prefix rectangle, a tree path, a subtree, a Manhattan ball, or a string prefix/substring locus.

Step 2: Intermediate Algebraic / Logical Representation

Before drawing a single data-structure node, write down the exact algebraic role of the transition family \((A_k, B_k)\) in the optimization objective. Across all network flow problems, dense transition rules fall into two fundamentally different algebraic regimes:

  1. Regime I — Unbundled Pairwise Implication Closure (Pairwise-Infinite): Every pair \((u, v) \in A_k \times B_k\) independently enforces a hard logical implication \(x_u \le x_v\) (i.e., if \(u \in S\) then \(v \in S\), or else pay \(\infty\)):

    \[\Psi_k^{\text{imp}}(x) = \sum_{u \in A_k} \sum_{v \in B_k} \infty \cdot x_u (1 - x_v) = \infty \cdot \left[\left(\max_{u \in A_k} x_u\right) > \left(\min_{v \in B_k} x_v\right)\right]\]

  2. Regime II — Bundled-Capacity Cut Penalty or Flow Routing (Bundled-Finite): Either the entire block \((A_k, B_k)\) shares a single bundled penalty \(c_k < \infty\) paid at most once if any \(u \in A_k\) is chosen (\(x_u = 1\)) while at least one \(v \in B_k\) is not chosen (\(x_v = 0\)):

    \[\Psi_k^{\text{bundle}}(x) = c_k \cdot \max_{u \in A_k,\, v \in B_k} x_u (1 - x_v) = \min_{z_k \in \{0, 1\}} \left\{ c_k \cdot z_k + \sum_{u \in A_k} \infty \cdot x_u(1 - z_k) + \sum_{v \in B_k} \infty \cdot (z_k \text{ without } c_k\text{-cut})(1 - x_v) \right\}\]

    or in the dual circulation / MCMF perspective, rule \(k\) is a shared pipe that can transport up to \(c_k\) units of flow from vertices in \(A_k\) to vertices in \(B_k\) at unit cost \(w_k\):

    \[\sum_{u \in A_k} f_{u \to k} = f_k = \sum_{v \in B_k} f_{k \to v} \le c_k, \qquad \text{Cost}_k = w_k \cdot f_k\]

Step 3: Reverse-Engineering Scratchpad (Mechanical Graph Compilation)

Suppose we construct an auxiliary Virtual Hub DAG \(\mathcal{H} = (V_{\mathcal{H}}, E_{\mathcal{H}})\) containing the original vertices \(V \subseteq V_{\mathcal{H}}\) plus virtual hub nodes \(V_{\text{hub}} = V_{\mathcal{H}} \setminus V\) whose internal edges carry capacity \(\infty\) and cost \(0\). To replace the \(\Theta(|A_k|\cdot |B_k|)\) direct edges of rule \(k\):

  • Suppose each target subset \(B_k\) can be decomposed as the union of reachability sets of \(r_k \ll |B_k|\) Out-Hubs \(\{h_1^+, \dots, h_{r_k}^+\} \subseteq V_{\text{hub}}\):

    \[B_k = \bigcup_{j=1}^{r_k} \operatorname{Reach}_{\mathcal{H}^+}(h_j^+)\]

  • Symmetrically, suppose each source subset \(A_k\) can be decomposed as the union of co-reachability sets of \(\ell_k \ll |A_k|\) In-Hubs \(\{h_1^-, \dots, h_{\ell_k}^-\} \subseteq V_{\text{hub}}\):

    \[A_k = \bigcup_{i=1}^{\ell_k} \operatorname{CoReach}_{\mathcal{H}^-}(h_i^-)\]

  • Finally, introduce a Bridge Bottleneck Pair \((b_{\text{in}, k}, b_{\text{out}, k})\) connected by a single bridge edge \(b_{\text{in}, k} \xrightarrow{\text{cap } c_k, \text{ cost } w_k} b_{\text{out}, k}\), wire every \(h_i^- \xrightarrow{\infty, 0} b_{\text{in}, k}\), and wire \(b_{\text{out}, k} \xrightarrow{\infty, 0} h_j^+\). (When \(|A_k| = 1\), i.e. \(A_k = \{u\}\), we omit the In-Hubs and wire \(u \xrightarrow{c_k, w_k} b_{\text{out}, k}\) directly; when \(c_k = \infty\) and \(w_k = 0\) as well, we wire \(u \xrightarrow{\infty, 0} h_j^+\) directly.)

1.2 Theorem 22.1: Hub-Factorization Cut-Preservation & The Idempotency Boundary

When is it legal for the hub cover \(B_k = \bigcup_{j=1}^{r_k} \operatorname{Reach}(h_j^+)\) to have overlapping sets (as in a Sparse Table or overlapping binary-lifting blocks), and when must the decomposition be a strictly disjoint partition with a unique path in \(\mathcal{H}\)? The following theorem provides the exact boundary.

ImportantTheorem 22.1 (Hub-Factorization Cut-Preservation & The Idempotency Boundary)

Let \(G_{\text{dense}}\) be the network formed by replacing each rule \((A_k, B_k, c_k, w_k)\) with a single bridge \(b_{\text{in},k} \xrightarrow{c_k, w_k} b_{\text{out},k}\) connected directly to all \(u \in A_k\) and all \(v \in B_k\) by \((\infty, 0)\) edges, and let \(G_{\mathcal{H}}\) be the Virtual Hub DAG network compiled via In-Hubs \(\mathcal{H}^-\) and Out-Hubs \(\mathcal{H}^+\).

  1. Exactness of Reachability Closures: Suppose every internal edge of \(\mathcal{H}^-\) and \(\mathcal{H}^+\) has capacity \(\infty\) and cost \(0\), and no internal hub in \(\mathcal{H}^+\) can reach any node outside \(B_k\) (nor can any node outside \(A_k\) reach an In-Hub of \(A_k\)). Then:

    • Min-Cut Equivalence: In any finite-capacity \(S\)-\(T\) cut of \(G_{\mathcal{H}}\), no \((\infty, 0)\) hub edge can be severed. For each rule \(k\), if there exist \(u \in A_k \cap S\) and \(v \in B_k \cap T\), then \(b_{\text{in},k}\) is forced into \(S\) (by upward \((\infty, 0)\) edges from \(u\)) and \(b_{\text{out},k}\) is forced into \(T\) (by downward \((\infty, 0)\) edges to \(v\)). Hence the bridge edge \(b_{\text{in},k} \to b_{\text{out},k}\) of capacity \(c_k\) is cut if and only if \((A_k \cap S) \neq \emptyset\) and \((B_k \cap T) \neq \emptyset\). Thus \(\text{MinCut}(G_{\mathcal{H}}) = \text{MinCut}(G_{\text{dense}})\).
    • Idempotency vs. Disjointness:
      • If \(c_k = \infty\) and \(w_k = 0\) (Regime I: pure logical implication closure), Boolean OR is idempotent (\(1 \vee 1 = 1\)). Overlapping covers \(\bigcup_{j=1}^{r_k} \operatorname{Reach}(h_j^+) = B_k\) (such as Sparse Table intervals or overlapping binary-lifting blocks) preserve the minimum cut without needing a bridge node or disjointness!
      • If \(c_k < \infty\) is placed directly on individual query-to-hub edges \(u \to h_j^+\) without a single bottleneck bridge \(b_{\text{in},k} \to b_{\text{out},k}\), or if \(w_k \neq 0\) in an MCMF network where multiple paths between \(u \in A_k\) and \(v \in B_k\) carry different costs or allow double-routing, then overlapping covers corrupt the objective (charging \(2c_k\) instead of \(c_k\) in a cut). To ensure exact bijection of flows and cuts, one must either (a) funnel the rule through a single bridge edge \(b_{\text{in},k} \xrightarrow{c_k, w_k} b_{\text{out},k}\), or (b) decompose \(B_k = \bigsqcup_{j=1}^{r_k} \operatorname{Reach}(h_j^+)\) into a disjoint union where each leaf \(v \in V\) has a single finite-capacity entry/exit edge \((v_{\text{in}}, v_{\text{out}})\).

2. The Seven Virtual Hub Architectures & Broken-Gadget Counterexamples

Once you understand Theorem 22.1, every data-structure-accelerated flow graph in competitive programming is simply a choice of which hierarchical index \(\mathcal{H}\) decomposes the problem’s query predicates \(A_k, B_k\) into \(O(\log^d N)\) canonical hubs.

2.1 Architecture 1: 1D Dual Segment Trees (Out-Tree & In-Tree)

To support range transitions over \(V = \{1, 2, \dots, N\}\), we build two separate segment trees sharing the exact same \(N\) leaf vertices:

  • The Out-Tree \(\mathcal{T}_{\text{out}}\) (Top-Down, for \(u \to [l, r]\)): Every internal node \(p\) corresponding to \([L, R]\) has directed edges to its children:

    \[p_{\text{out}} \xrightarrow{\text{cap } \infty,\text{ cost } 0} lc_{\text{out}}, \qquad p_{\text{out}} \xrightarrow{\text{cap } \infty,\text{ cost } 0} rc_{\text{out}}\]

    At \(L = R = i\), the leaf node \(p_{\text{out}}\) is identified directly with original vertex \(i\) (or wired \(p_{\text{out}} \xrightarrow{\infty, 0} i\)). Any query \(u \xrightarrow{c, w} [l, r]\) decomposes \([l, r]\) into \(r_k \le 2\lceil\log_2 N\rceil\) disjoint canonical nodes \(\{h_1^+, \dots, h_{r_k}^+\}\) and attaches through a single bottleneck hub \(b_k\):

    \[u \xrightarrow{c, w} b_k, \qquad b_k \xrightarrow{\infty, 0} h_j^+ \quad (j = 1, \dots, r_k)\]

    (If \(c = \infty\) and \(w = 0\), we omit \(b_k\) and add \(u \xrightarrow{\infty, 0} h_j^+\) directly.)

  • The In-Tree \(\mathcal{T}_{\text{in}}\) (Bottom-Up, for \([l, r] \to v\)): Every internal node \(p_{\text{in}}\) receives directed edges from its children:

    \[lc_{\text{in}} \xrightarrow{\text{cap } \infty,\text{ cost } 0} p_{\text{in}}, \qquad rc_{\text{in}} \xrightarrow{\text{cap } \infty,\text{ cost } 0} p_{\text{in}}\]

    Any range-to-range transition \([l_1, r_1] \xrightarrow{c, w} [l_2, r_2]\) creates one bridge edge \(b_{\text{in}} \xrightarrow{c, w} b_{\text{out}}\), wires the \(O(\log N)\) In-Tree nodes of \([l_1, r_1]\) into \(b_{\text{in}}\), and wires \(b_{\text{out}}\) into the \(O(\log N)\) Out-Tree nodes of \([l_2, r_2]\).

  • Complexity: \(|V_{\mathcal{H}}| \le 3N + 2K\), \(|E_{\mathcal{H}}| = O(N + K \log N)\).

2.2 Architecture 2: Prefix Persistent Segment Tree (主席树) & The Duplicate-Key Chaining Fix

Suppose a transition from index \(i\) targets all earlier indices \(j < i\) whose keys \(a_j\) lie in a value range \([L_i, R_i]\):

\[B_i = \{ j \in \{1, \dots, i-1\} : L_i \le a_j \le R_i \}\]

This is a 2D orthogonal half-infinite box \([1, i-1] \times [L_i, R_i]\). A naive 2D Segment Tree costs \(O(N \log^2 N)\) vertices and edges, which often exceeds memory limits in Dinic. Instead, we sweep \(i = 1, 2, \dots, N\) and maintain a Persistent Out-Segment Tree over the coordinate-compressed value domain \([1, U]\) (\(U \le N\)):

  1. Let \(\text{root}_{i-1}\) be the root of the persistent segment tree after inserting indices \(1, 2, \dots, i-1\).
  2. Before inserting \(i\), we query \(\text{root}_{i-1}\) on the value interval \([L_i, R_i]\), obtaining \(O(\log N)\) persistent hub nodes that reach only indices \(j \le i - 1\) with \(a_j \in [L_i, R_i]\). We add edges from \(i\) (or \(i\)’s auxiliary conflict node) to these \(O(\log N)\) hubs.
  3. Then we insert index \(i\) at position \(\text{pos}(a_i)\) to create \(\text{root}_i\) by cloning the \(O(\log N)\) nodes along the root-to-leaf path: each newly created internal node \(u_{\text{new}}\) connects \(u_{\text{new}} \xrightarrow{\infty, 0} lc(u_{\text{new}})\) and \(u_{\text{new}} \xrightarrow{\infty, 0} rc(u_{\text{new}})\).
WarningThe Duplicate-Key Leaf Chaining Fix (主席树重值叶子串联)

What happens if two indices \(j < i\) have the exact same value \(a_j = a_i\)? When creating version \(\text{root}_i\), the leaf node for value \(a_i\) is replaced by a new leaf \(u_{\text{new}}\). If \(u_{\text{new}}\) only points to original vertex \(i\), then the older vertex \(j\) (which was attached to the overwritten leaf \(u_{\text{old}}\) in version \(\text{root}_{i-1}\)) becomes completely unreachable from \(\text{root}_i\) and all subsequent versions \(\text{root}_k\) (\(k \ge i\))!

Mandatory Fix: Whenever you clone a node \(u_{\text{new}}\) from an existing node \(u_{\text{old}}\) during persistent path-copying (or specifically at the leaf \(L = R\)), you must add a version-chaining edge:

\[u_{\text{new}} \xrightarrow{\text{cap } \infty,\text{ cost } 0} u_{\text{old}}\]

alongside \(u_{\text{new}} \xrightarrow{\infty, 0} i\). For internal nodes \(L < R\), connecting \(u_{\text{new}} \to lc(u_{\text{new}}), rc(u_{\text{new}})\) already covers the unchanged child and the updated child (which in turn chains to its old leaf), or you can chain \(u_{\text{new}} \to u_{\text{old}}\) at every cloned node. This guarantees that \(\text{root}_i\) reaches the entire multiset of indices \(\{j \le i : a_j = v\}\) in \(O(N \log N)\) total vertices and edges.

2.3 Architecture 3: Sweep-Line + Persistent Segment Tree Subtree Splicing

In 2D grid matching problems with \(Q\) forbidden rectangles (such as [CF 793G] Oleg and chess, Problem #171), the set of available column intervals changes dynamically as we sweep across rows \(x = 1 \dots N\). Rather than rebuilding a segment tree at every row, we maintain a persistent Out-Tree over rows \([1, N]\) where:

  • Initially (\(y = 1\)), a master Out-Tree covers all rows \([1, N]\) with leaf \(r\) wired \(r \xrightarrow{1} T\).
  • When a forbidden rectangle \([x_1, x_2] \times [y_1, y_2]\) starts at column \(y_1\), we update \([x_1, x_2]\) in the persistent tree by setting those canonical segment-tree pointers to 0 (null), severing reachability to rows \([x_1, x_2]\) in \(O(\log N)\) new persistent nodes.
  • When that rectangle ends at column \(y_2 + 1\), how do we restore rows \([x_1, x_2]\) without paying \(\Theta(x_2 - x_1)\)? Because \([x_1, x_2]\) was untouched during \([y_1, y_2]\), we simply splice the canonical subtrees of \([x_1, x_2]\) directly from the initial master tree \(\text{root}_0\) back into the current persistent version in \(O(\log N)\) time!
  • At each column \(y\), the column source edge \(S \xrightarrow{1} \text{col}_y \xrightarrow{\infty} \text{root}_y\) automatically connects column \(y\) to all currently unblocked rows. Because every persistent node has only \(\infty\)-capacity internal edges and unit capacities sit only at \(S \to \text{col}_y\) and \(\text{row}_x \to T\), Dinic runs in \(O(E\sqrt{V}) = O((N + Q \log N)\sqrt{N})\)!

2.4 Architecture 4: CDQ Divide-and-Conquer + 1D Bi-Directional Value Chain (CDQ 分治优化建图)

Consider a 2D transition with an additive 1D Manhattan cost over indices and values ([SDOI2019] 通信, Problem #172):

\[i \xrightarrow{\text{cap } 1,\text{ cost } |a_i - a_j|} j \qquad \text{for all } 1 \le j < i \le N\]

A Persistent Segment Tree can isolate the subset \(\{j < i\}\), but it cannot assign the continuous cost \(|a_i - a_j|\) because \(|a_i - a_j|\) depends on both \(a_i\) and \(a_j\). How do we decouple both the order constraint \(j < i\) and the absolute-value cost \(|a_i - a_j|\) simultaneously?

  1. Eliminate \(j < i\) via CDQ Divide-and-Conquer: Call \(\text{CDQ}(L, R)\) on the index interval \([L, R]\) with midpoint \(M = \lfloor(L+R)/2\rfloor\). Every valid pair \((j, i)\) with \(L \le j < i \le R\) is uniquely captured at the recursion level where \(j \in [L, M]\) (left half) and \(i \in [M+1, R]\) (right half).

  2. Eliminate \(|a_i - a_j|\) via a 1D Bi-Directional Sorted Value Chain: Inside a single CDQ step \((L, R)\), collect all distinct values \(v_1 < v_2 < \dots < v_k\) appearing among \(\{a_t : t \in [L, R]\}\) (\(k \le R - L + 1\)). Create \(k\) chain hubs \(h_1, h_2, \dots, h_k\) connected into a bidirectional adjacent chain where consecutive hubs carry the exact difference cost:

    \[h_m \xrightarrow{\text{cap } \infty,\text{ cost } v_{m+1} - v_m} h_{m+1}, \qquad h_{m+1} \xrightarrow{\text{cap } \infty,\text{ cost } v_{m+1} - v_m} h_m \qquad (1 \le m < k)\]

  3. Attach Right-Half Sources and Left-Half Sinks:

    • For every right-half index \(i \in [M+1, R]\) with \(a_i = v_m\), add a directed zero-cost entry edge \(i_{\text{out}} \xrightarrow{\infty, 0} h_m\).
    • For every left-half index \(j \in [L, M]\) with \(a_j = v_{m'}\), add a directed zero-cost exit edge \(h_{m'} \xrightarrow{\infty, 0} j_{\text{in}}\).

Because the hubs inside a single CDQ slab only allow entry from \([M+1, R]\) and exit to \([L, M]\), flow can only travel from some \(i \in [M+1, R]\) to some \(j \in [L, M]\)! And the shortest path along the bidirectional chain from \(h_m\) to \(h_{m'}\) has cost \(\sum |\Delta v| = |v_m - v_{m'}| = |a_i - a_j|\). Across all \(\log_2 N\) levels of the CDQ recursion tree, the total number of hubs and edges is strictly \(O(N \log N)\)!

2.5 Architectures 5–7: Tree Paths, 2D KD-Trees / Manhattan Hubs, and String Automata

The same Virtual Hub principle extends cleanly to trees, 2D metric spaces, and strings:

  • Architecture 5 — Tree Path Sparsification (HLD + Prefix Chain vs. Binary Lifting):
    • Regime I (\(\infty\)-capacity Min-Cut / 2-SAT on tree paths): By Theorem 22.1, overlapping covers are legal! Use Binary Lifting (倍增优化建图) where \(\text{up}[u][k]\) covers the \(2^k\) ancestors of \(u\) with \(\text{up}[u][k] \xrightarrow{\infty} \text{up}[u][k-1]\) and \(\text{up}[u][k] \xrightarrow{\infty} \text{up}[\text{anc}(u, 2^{k-1})][k-1]\). Then any path \(u \leftrightarrow v\) (with \(l = \operatorname{LCA}(u, v)\)) is covered by at most 4 hubs in \(O(1)\) edges per query!
    • Regime II (Finite-capacity or MCMF on tree paths): Overlapping covers are illegal. Use Heavy-Light Decomposition (HLD) to split \(u \leftrightarrow v\) into \(O(\log N)\) disjoint heavy-chain intervals. Furthermore, in the 90% of problems where queries are ancestor-to-descendant paths, each heavy chain interval \([top_c, x]\) is a prefix of the heavy chain — so a simple \(O(N)\) 1D Prefix Out-Chain \(h_1 \xrightarrow{\infty} h_2 \dots\) along each heavy chain replaces the segment tree, reducing \(O(N \log^2 N)\) to \(O(N \log N)\)!
  • Architecture 6 — 2D KD-Tree Bounding-Box Hubs & 4-Sign Manhattan Hubs:
    • 2D Orthogonal Range Queries under Tight Memory ([NOI2019] 弹跳, Problem #176): A 2D Segment Tree uses \(O(N \log^2 N)\) nodes. A 2D KD-Tree alternating \(x\)- and \(y\)-median splits uses strictly \(2N - 1 = O(N)\) nodes, and each node stores its exact axis-aligned bounding box \([x_{\min}, x_{\max}] \times [y_{\min}, y_{\max}]\) so rectangle queries decompose into \(O(\sqrt{N})\) canonical subtree hubs.
    • 2D Manhattan Max-Cost Matching ([AGC 034D] Manhattan Max Matching): Since \(|x_i - x_j| + |y_i - y_j| = \max_{s_x, s_y \in \{\pm 1\}} \big[(s_x x_i + s_y y_i) + (-s_x x_j - s_y y_j)\big]\), any complete bipartite graph with Manhattan edge weights factors through just 4 intermediate sign hubs \(H_{(+1,+1)}, H_{(+1,-1)}, H_{(-1,+1)}, H_{(-1,-1)}\), collapsing \(O(N^2)\) edges to \(4N\) edges!
  • Architecture 7 — String Automaton Link Trees (SAM / AC Automaton / PAM): Whenever choosing substring \(s\) forces choosing all substrings containing \(s\) (or all suffixes of \(s\)), the implication closure is already encoded by the Suffix Automaton (SAM) parent-link tree (link[u] <-> u), the Aho–Corasick fail tree, or the Palindromic Tree (PAM) fail links, reducing \(\Theta(|S|^2)\) substring implications to \(O(|S|)\) tree edges ([NOI2017] 蚯蚓排队, [CF 616F]).

2.6 Broken-Gadget Counterexamples (FM-22 & H-22): Two Fatal Hub Bugs

Let us trace a concrete 4-leaf (\(N = 4\)) segment tree on \(V = \{1, 2, 3, 4\}\) to prove why two tempting implementation shortcuts completely corrupt the flow network.

CautionBroken Gadget 22A (FM-22): Finite Capacity on Internal Segment-Tree Edges vs. Query Bottleneck

Scenario: Suppose leaves \(1, 2, 3, 4\) can each absorb \(1\) unit of flow to the sink (\(i \xrightarrow{\text{cap } 1} T\)). We have two range-supply rules:

  • Rule A (\(u_A \to [1, 2]\) with total capacity \(1\)), and
  • Rule B (\(u_B \to [1, 2]\) with total capacity \(1\)).

Together, Rules A and B should be able to deliver \(1 + 1 = 2\) units of flow to leaves \(\{1, 2\}\) (e.g., \(u_A \to 1 \to T\) and \(u_B \to 2 \to T\), Max-Flow \(= 2\)).

  • Broken Construction: A contestant forgets to put \(\infty\) capacity on the internal Out-Tree node \(h_{[1,2]}\) or puts capacity \(1\) on the internal tree edge \(\text{root}_{[1,4]} \xrightarrow{1} h_{[1,2]}\) (or reuses a single finite-capacity edge on \(h_{[1,2]}\)). Then both \(u_A\) and \(u_B\) are throttled by the shared internal edge of capacity \(1\), yielding a false Max-Flow of \(1\) instead of \(2\)!
  • Reverse Broken Construction: Conversely, suppose a single Rule C (\(u_C \to [1, 3]\) with bundled capacity \(1\)) is decomposed into canonical Out-Tree nodes \(h_{[1,2]}\) and \(h_{[3,3]}\). If the contestant wires \(u_C \xrightarrow{\text{cap } 1} h_{[1,2]}\) and \(u_C \xrightarrow{\text{cap } 1} h_{[3,3]}\) without a single bottleneck edge \(S \xrightarrow{1} u_C\) (or bridge \(u_C \xrightarrow{1} b_C\)), then \(u_C\) pushes \(1\) unit through \(h_{[1,2]} \to 1\) and \(1\) unit through \(h_{[3,3]} \to 3\), yielding a false Max-Flow of \(2\) instead of \(1\)!
  • The Invariant: Internal tree edges of \(\mathcal{T}_{\text{out}}\) and \(\mathcal{T}_{\text{in}}\) must always have capacity \(\infty\) and cost \(0\). Finite capacity \(c_k\) and cost \(w_k\) belong exclusively on the unique bottleneck bridge \(b_{\text{in},k} \xrightarrow{c_k, w_k} b_{\text{out},k}\) (or on the leaf attachment edges \(v_{\text{in}} \to v_{\text{out}}\)).
CautionBroken Gadget 22B (H-22): Merging In-Tree and Out-Tree into One Bidirectional Hub Tree

Scenario: On \(V = \{1, 2, 3, 4\}\), suppose we want to add a range-to-range rule \([1, 2] \xrightarrow{\text{cap } 1} [3, 4]\). To save memory, a contestant builds a single segment tree where every parent-child edge is bidirectional with capacity \(\infty\): \(p \xleftrightarrow{\infty} lc\) and \(p \xleftrightarrow{\infty} rc\).

  • The Fatal Leak: In this merged tree, leaf \(1\) can walk up to \(h_{[1,2]} \xrightarrow{\infty} \text{root}_{[1,4]}\) and then walk down to \(h_{[3,4]} \xrightarrow{\infty} \text{leaf } 3\) using only internal tree edges of capacity \(\infty\) and cost \(0\) — even if we never added any query edge between \([1, 2]\) and \([3, 4]\)! Every vertex in \(\{1, 2, 3, 4\}\) becomes mutually reachable with capacity \(\infty\) and cost \(0\), collapsing the entire graph into a single giant connected component.
  • The Invariant: \(\mathcal{T}_{\text{in}}\) (strictly bottom-up: \(\text{child} \to \text{parent}\)) and \(\mathcal{T}_{\text{out}}\) (strictly top-down: \(\text{parent} \to \text{child}\)) must be two disjoint sets of internal hub vertices, touching only at the \(N\) bottom leaves and across explicit query bridges \(b_{\text{in}, k} \to b_{\text{out}, k}\).

3. Module 22B — When Bipartiteness Fails: Odd Cycles, Half-Integrality & The Tutte–Berge Formula

Throughout Part II (Chapters 07–11), our entire matching and min-cut toolkit rested on a single foundational pillar: total unimodularity of the bipartite incidence matrix \(A\). When \(G = (L \sqcup R, E)\) is bipartite, the linear program

\[\max \sum_{e \in E} x_e \quad \text{s.t.} \quad \sum_{e \in \delta(v)} x_e \le 1 \;\; (\forall v \in V), \quad x_e \ge 0\]

has exclusively integral extreme points \(x_e \in \{0, 1\}\), and its dual LP is the Minimum Vertex Cover LP \(\min \sum_{v \in V} y_v\) s.t. \(y_u + y_v \ge 1\), giving König’s Theorem \(\nu(G) = \tau(G)\).

What breaks the moment \(G\) contains a single odd cycle?

3.1 The Triangle Counterexample (\(K_3\)) and the Failure of the Bipartite Double Cover (FM-22 / H-08)

Consider the simplest non-bipartite graph: a triangle \(K_3\) on vertices \(\{1, 2, 3\}\) with edges \(e_{12}, e_{23}, e_{31}\).

  • Integral Matching vs. Integral Vertex Cover: At most one edge of \(K_3\) can be chosen without sharing an endpoint, so \(\nu(K_3) = 1\). Conversely, at least two vertices must be chosen to cover all three edges, so \(\tau(K_3) = 2\). König’s equality \(\nu = \tau\) fails!
  • Half-Integral LP Relaxation: In the degree-constrained fractional matching LP above, setting \(x_{12} = x_{23} = x_{31} = \frac{1}{2}\) satisfies \(\sum_{e \in \delta(v)} x_e = \frac{1}{2} + \frac{1}{2} = 1\) at every vertex and achieves a fractional objective of \(\frac{3}{2} > 1 = \nu(K_3)\)! Symmetrically, the dual fractional vertex cover sets \(y_1 = y_2 = y_3 = \frac{1}{2}\) with objective \(\frac{3}{2} < 2 = \tau(K_3)\). By the Balinski–Nemhauser–Trotter Theorem, the extreme points of the fractional matching/vertex-cover polytope on any general graph are half-integral (\(x_e, y_v \in \{0, \frac{1}{2}, 1\}\)), where the \(\frac{1}{2}\)-components form vertex-disjoint odd cycles.
CautionBroken Gadget 22C (FM-22 / H-08): Why Splitting \(v \mapsto (v_{\text{out}}, v_{\text{in}})\) Fails on General Graphs

When faced with a non-bipartite matching problem in contest, a classic trap is to construct the Bipartite Double Cover \(G \times K_2\): split every vertex \(v \in V\) into \(v_{\text{out}} \in L\) and \(v_{\text{in}} \in R\), replace every undirected edge \(\{u, v\} \in E\) with two directed bipartite edges \(u_{\text{out}} \to v_{\text{in}}\) and \(v_{\text{out}} \to u_{\text{in}}\), run Dinic, and divide the maximum flow by \(2\).

Why It Fails on \(K_3\): On \(K_3 = \{1, 2, 3\}\), the bipartite double cover has a perfect matching of size \(3\):

\[M_{\text{double}} = \{(1_{\text{out}}, 2_{\text{in}}),\; (2_{\text{out}}, 3_{\text{in}}),\; (3_{\text{out}}, 1_{\text{in}})\}\]

Dividing by \(2\) reports a matching size of \(3 / 2 = 1.5\) (or \(\lfloor 3/2 \rfloor = 1\), hiding which vertices are actually matched). Worse, on two disjoint triangles \(K_3 \sqcup K_3\) (where true \(\nu(G) = 2\)), the bipartite double cover finds a perfect matching of size \(6\) and reports \(6/2 = 3\)! Why? Because the bipartite double cover computes the maximum 2-factor / half-integral matching \(\nu_{\text{frac}}(G)\) (packing vertex-disjoint edges and odd cycles), completely ignoring the symmetry constraint \(f(u_{\text{out}} \to v_{\text{in}}) = f(v_{\text{out}} \to u_{\text{in}})\).

3.2 The Tutte–Berge Formula & Gallai–Edmonds Canonical Decomposition

How do we repair König’s duality when odd cycles can trap at most \(\frac{|C|-1}{2}\) matched edges and leave at least \(1\) vertex of each odd component exposed? Suppose we delete a barrier set of vertices \(U \subseteq V\) from \(G\). Look at the connected components of \(G \setminus U\) that have an odd number of vertices; let \(\operatorname{odd}(G \setminus U)\) denote the number of such odd-sized connected components.

In any valid matching \(M\) of \(G\), every odd component \(C_i\) of \(G \setminus U\) (\(|V(C_i)| = 2k_i + 1\)) has an odd number of vertices. Any edge of \(M\) with both endpoints inside \(C_i\) pairs up \(2\) vertices of \(C_i\), so at least one vertex of \(C_i\) must either be unmatched in \(M\) or be matched to a vertex in the barrier \(U\)! Since \(U\) has only \(|U|\) vertices in total, \(U\) can rescue at most \(|U|\) odd components of \(G \setminus U\). The remaining \(\max(0, \operatorname{odd}(G \setminus U) - |U|)\) odd components must each contain at least one unmatched vertex!

ImportantTheorem 22.2 (The Tutte–Berge Formula & Gallai–Edmonds Canonical Decomposition)

For any undirected graph \(G = (V, E)\), the number of unmatched vertices in a maximum matching is given by the maximum deficiency over all barrier sets \(U \subseteq V\):

\[|V| - 2\nu(G) = \max_{U \subseteq V} \big(\operatorname{odd}(G \setminus U) - |U|\big) \quad \Longleftrightarrow \quad \nu(G) = \frac{1}{2} \min_{U \subseteq V} \big(|V| + |U| - \operatorname{odd}(G \setminus U)\big)\]

Moreover, there exists a canonical, matching-independent 3-way partition of the vertex set \(V = D(G) \sqcup A(G) \sqcup C(G)\) — the Gallai–Edmonds Decomposition — defined uniquely by:

  • \(D(G)\) (Inessential / Deficient Vertices): The set of vertices \(v \in V\) that are missed by at least one maximum matching of \(G\) (i.e., \(\nu(G \setminus \{v\}) = \nu(G)\)).
  • \(A(G)\) (Barrier / Essential Neighbor Vertices): The set of vertices \(u \in V \setminus D(G)\) that are adjacent in \(G\) to at least one vertex in \(D(G)\).
  • \(C(G)\) (Critical / Even-Component Vertices): The remaining vertices \(V \setminus (D(G) \cup A(G))\).

Structural Properties of \((D(G), A(G), C(G))\):

  1. Canonical Tutte Barrier: Choosing \(U = A(G)\) achieves the exact maximum in the Tutte–Berge formula: \(\operatorname{odd}(G \setminus A(G)) - |A(G)| = |V| - 2\nu(G)\).
  2. Even Components \(C(G)\): Every connected component of \(G[C(G)]\) has an even number of vertices and possesses a perfect matching in every maximum matching of \(G\).
  3. Factor-Critical Odd Components \(D(G)\): Every connected component \(K\) of \(G[D(G)]\) has an odd number of vertices and is factor-critical — deleting any single vertex \(v \in K\) leaves a subgraph \(K \setminus \{v\}\) that has a perfect matching of size \(\frac{|K|-1}{2}\)!
  4. Every Maximum Matching’s Anatomy: In every maximum matching \(M\) of \(G\): (a) \(G[C(G)]\) is perfectly matched internally; (b) every vertex \(u \in A(G)\) is matched to a vertex in a distinct factor-critical component \(K_u \subseteq D(G)\); and (c) the remaining \(\operatorname{odd}(G[D(G)]) - |A(G)|\) components of \(D(G)\) each have \(1\) exposed vertex and are matched internally on their remaining \(|K|-1\) vertices.

Extracting \(D(G), A(G), C(G)\) in \(O(N^3)\) and the General-Graph Walk Game

Once we have found any maximum matching \(M\) via Edmonds’ Blossom algorithm (Section 4), how do we extract \((D(G), A(G), C(G))\)?

  • Start a multi-source alternating Blossom BFS simultaneously from all \(M\)-unmatched vertices \(r \in V \setminus V(M)\) as outer (even-distance, vis = 1) roots.
  • Contract any odd blossoms encountered during the search just as in Edmonds’ algorithm.
  • When the alternating forest saturates without finding an augmenting path:
    • \(D(G)\) is the exact set of vertices with vis == 1 (outer / even-alternating-distance vertices from unmatched roots, including all vertices inside contracted blossoms, because rotating an odd blossom makes every vertex inside it reachable at even alternating length!).
    • \(A(G)\) is the exact set of vertices with vis == 2 (inner / odd-alternating-distance vertices).
    • \(C(G)\) is the exact set of unvisited vertices with vis == 0.

Application to 2-Player Walk Games on General Graphs ([JSOI2009] 游戏 on General Graphs / QOJ #5437): A token starts at \(s \in V\), and two players alternately move the token to an unvisited neighbor; the last player to move wins. Just as on bipartite graphs (Chapter 07), the first player has a winning strategy starting from \(s\) if and only if \(s\) belongs to EVERY maximum matching of \(G\) (\(\nu(G \setminus \{s\}) < \nu(G)\)) — which by Theorem 22.2 holds if and only if \(s \notin D(G)\) (i.e. \(s \in A(G) \cup C(G)\))!

4. Edmonds’ Blossom Contraction (带花树), Non-Bipartite Gadgets & Tutte Pfaffians

Why does standard bipartite alternating BFS fail on a general graph? Suppose we grow an alternating tree from an unmatched root \(r\) (vis[r] = 1, outer) where tree edges alternate:

\[r \xrightarrow{\text{unmatched}} u_1 \xrightarrow{\text{matched}} v_1 \xrightarrow{\text{unmatched}} u_2 \xrightarrow{\text{matched}} \dots\]

In a bipartite graph, an unmatched edge from an outer node (vis = 1) can only lead to an opposite-parity vertex (vis = 0 or vis = 2). In a general graph, however, an unmatched edge \((u, v)\) can connect two outer vertices (vis[u] == 1 and vis[v] == 1)! Tracing \(u\) and \(v\) back to their lowest common ancestor \(b = \operatorname{LCA}(u, v)\) in the alternating tree (taking the current DSU blossom representatives) reveals an odd alternating cycle \(B\) of length \(2k + 1\) — a Blossom (花) — whose base \(b\) (花托) is the unique vertex in \(B\) not matched to another vertex inside \(B\).

4.1 Proof of Edmonds’ Blossom Shrinking Theorem & Lazy DSU Implementation

ImportantTheorem 22.3 (Edmonds’ Blossom Shrinking Theorem, 1965)

Let \(M\) be a matching in \(G\), and let \(B\) be a blossom of length \(2k+1\) with base \(b\) discovered along an even-length alternating walk \(P_b\) from an unmatched root \(r\) to \(b\). Let \(G / B\) be the graph obtained by contracting all \(2k+1\) vertices of \(B\) into a single super-vertex \(v_B\), and let \(M / B\) be the induced matching on \(G / B\). Then \(G\) has an \(M\)-augmenting path if and only if \(G / B\) has an \((M / B)\)-augmenting path.

Proof (\(\Longleftarrow\), Lifting an Augmenting Path Out of \(B\)): This is the constructive direction that makes the algorithm work. By rotating the alternating path \(P_b\) first if necessary, we may assume \(b\) is itself an unmatched root (\(P_b = \emptyset\)). Suppose \(P'\) is an \((M/B)\)-augmenting path in \(G/B\). If \(P'\) does not touch \(v_B\), \(P'\) is already an \(M\)-augmenting path in \(G\). Otherwise, since \(v_B\) is unmatched in \(M/B\), \(P'\) starts at \(v_B\) and exits \(v_B\) via some unmatched edge \((w, x)\) where \(w \in B\) and \(x \notin B\). Because \(B\) is an odd cycle of \(2k+1\) vertices where the \(2k\) vertices \(B \setminus \{b\}\) are paired by \(k\) edges of \(M\), traveling from the base \(b\) to any vertex \(w \in B\) around the cycle \(B\) in one direction uses an even number of edges (starting with an \(M\)-unmatched edge and ending with an \(M\)-matched edge at \(w\)), while traveling around \(B\) in the opposite direction uses an odd number of edges! We simply choose the even-length alternating arc inside \(B\) from \(b\) to \(w\) and append \((w, x)\) followed by the rest of \(P'\). This yields a valid simple \(M\)-augmenting path in \(G\)! \(\blacksquare\)

The \(O(N^3)\) Lazy DSU + LCA Blossom Algorithm Contract

Instead of physically rebuilding the graph \(G / B\) every time a blossom is found, we maintain a Disjoint Set Union array orig[x] storing the current blossom base \(b\) of vertex \(x\), alongside match[x] (matched partner), pre[x] (unmatched-edge predecessor in the alternating tree), and vis[x] (0 = unvisited, 1 = outer/even, 2 = inner/odd):

  1. Finding \(b = \operatorname{LCA}(u, v)\): Hop \(u \gets \text{orig}[\text{pre}[\text{match}[u]]]\) and \(v \gets \text{orig}[\text{pre}[\text{match}[v]]]\) alternately using a timestamp array tim[x] = timer until a vertex is visited twice.
  2. Contracting Both Sides (contract(u, v, b) and contract(v, u, b)): Walk \(x\) from \(u\) up to \(b\) (and symmetrically from \(v\) up to \(b\)):
    • Set pre[x] = y (where \((x, y)\) starts as the odd bridge \((u, v)\) and then steps up \(y \gets \text{match}[x], x \gets \text{pre}[y]\)). Why? If an augmenting path later exits the blossom through an originally inner vertex \(y\) (vis[y] == 2), pre[y] must point around the blossom bridge \((u, v)\) so the path traces the even-length arc around \(B\)!
    • Whenever vis[y] == 2 (an inner vertex on the cycle), flip it to outer (vis[y] = 1) and push \(y\) into the BFS queue so it can scan its unmatched incident edges!
    • Union both \(x\) and \(y\) into the base \(b\): if (orig[x] == x) orig[x] = b; if (orig[y] == y) orig[y] = b;.
  3. Why vis[v] == 2 Edges Are Ignored: If an outer vertex \(u\) sees an already-visited inner vertex \(v\) (vis[v] == 2), adding \((u, v)\) creates an even alternating cycle in the alternating tree, which neither augments \(M\) nor flips the parity of any inner vertex.

4.2 Canonical Non-Bipartite Gadgets for General Degree & Step-Function Objectives

Just as Project Selection (Chapter 09) has canonical min-cut gadgets, General Graph Matching has three canonical vertex-splitting & edge-subdivision gadgets that reduce non-unit capacities and concave/non-monotone degree step rewards to standard \(1\)-matching:

  1. The 2-Vertex Twin Gadget (Capacity \(2\) with Optional Internal Pairing — [CF 1089B]): Suppose a vertex \(v\) can match up to \(2\) neighbors, or if it matches fewer than \(2\) external neighbors, two leftover slots can pair with each other (worth \(+1\) match). Create two twin vertices \(v_1, v_2\), connect both \(v_1\) and \(v_2\) to all original neighbors \(u \in N(v)\), and add an internal edge \((v_1, v_2)\):
    • If \(2\) external neighbors match \(v_1\) and \(v_2\), \(v\) contributes \(2\) to the matching.
    • If \(0\) external neighbors match \(v\), the internal edge \((v_1, v_2)\) matches itself (+1).
    • If \(1\) external neighbor matches \(v_1\), \(v_2\) is free (contributing \(+1\) from the external edge).
  2. The 3-Vertex Triangle Blossom Gadget ([WC2016] 挑战 NPC, Problem #173): Suppose a basket \(j\) can accept \(c_j \in \{1, 2, 3\}\) balls, and we want every ball to be placed while maximizing the number of baskets that receive \(\le 1\) ball (equivalently, each basket gives \(+1\) bonus if it holds \(\le 1\) ball, and \(0\) bonus if it holds \(2\) or \(3\) balls).
    • Split basket \(j\) into three vertices \(b_{j,1}, b_{j,2}, b_{j,3}\), connect all three to every compatible ball \(i\), and add a single internal edge \((b_{j,2}, b_{j,3})\) between the second and third slots!
    • Check the maximum matching contribution of basket \(j\) as a function of the number of balls \(c_j \in \{0, 1, 2, 3\}\) assigned to it:
      • \(c_j = 0\) balls: \(b_{j,1}\) is unmatched, while \((b_{j,2}, b_{j,3})\) matches internally \(\implies \mathbf{+1}\) match.
      • \(c_j = 1\) ball: the ball matches \(b_{j,1}\), while \((b_{j,2}, b_{j,3})\) matches internally \(\implies \mathbf{+2}\) matches (\(1\) ball \(+ 1\) bonus!).
      • \(c_j = 2\) balls: the two balls match \(b_{j,1}\) and \(b_{j,2}\), breaking \((b_{j,2}, b_{j,3})\) \(\implies \mathbf{+2}\) matches (\(2\) balls \(+ 0\) bonus!).
      • \(c_j = 3\) balls: the three balls match \(b_{j,1}, b_{j,2}, b_{j,3}\) \(\implies \mathbf{+3}\) matches (\(3\) balls \(+ 0\) bonus!).
    • In every case, Basket \(j\)’s contribution to the matching is \(\text{balls}(j) + [c_j \le 1]\)!
WarningMandatory Two-Phase Blossom Ordering (先球后筐)

In the 3-Vertex Triangle Blossom Gadget above, if we immediately add all internal edges \((b_{j,2}, b_{j,3})\) and run Blossom in a single pass, could the solver leave \(1\) ball unmatched in order to save \(2\) internal basket edges? Actually, switching \(2\) balls from one basket to leave a basket empty preserves total matches, unless a ball has no valid basket at all or we need to guarantee that all \(N\) balls are matched first! Worse, if we build the graph dynamically, Phase 1 must first augment from all ball vertices \(i = 1 \dots N\) (ensuring all \(N\) balls are matched), and Phase 2 then attempts to augment from the internal basket vertices \(b_{j,2}, b_{j,3}\)! Because augmenting paths never unmatch an already-matched vertex, every ball matched in Phase 1 remains permanently matched throughout Phase 2, so Total Matches \(- N\) equals the exact maximum number of baskets with \(\le 1\) ball!

  1.     • If \(e\) is selected in the factor, \(e_u\) matches a clone in \(C_u\) and \(e_v\) matches a clone in \(C_v\) (consuming \(1\) degree at \(u\) and \(1\) at \(v\)).
    • If \(e\) is not selected, \(e_u\) and \(e_v\) match each other via \((e_u, e_v)\) (consuming \(0\) degree at \(u\) and \(v\)). Thus \(G\) has a \(d\)-factor iff this subdivided graph of \(\sum d_v + 2|E|\) vertices has a perfect matching!

4.3 Weighted Blossom LP Duals (带权带花树, UOJ #81)

To find a Maximum-Weight Matching in a general graph \(G = (V, E, w)\), why aren’t vertex potentials \(y_v\) (\(y_u + y_v \ge w_e\)) enough? Because on \(K_3\) with edge weights \(w = 10\), setting \(y_1 = y_2 = y_3 = 5\) gives \(\sum y_v = 15\), whereas the best integral matching has weight \(10\)!

Edmonds proved (1965) that adding the Odd-Set (Blossom) Inequalities makes the matching polytope 100% integral:

\[\max \sum_{e \in E} w_e x_e \quad \text{s.t.} \quad \sum_{e \in \delta(v)} x_e \le 1 \;\; (\forall v \in V), \quad \sum_{e \in E(B)} x_e \le \frac{|B|-1}{2} \;\; (\forall B \subseteq V, |B| \ge 3 \text{ odd}), \quad x_e \ge 0\]

In the Dual LP, we maintain a potential \(y_v \ge 0\) for every vertex \(v \in V\) and a Blossom Dual Variable \(z_B \ge 0\) for every non-trivial contracted odd blossom \(B\) (\(|B| = 2k+1 \ge 3\)), subject to the reduced-slack invariant:

\[\operatorname{slack}(u, v) = y_u + y_v - w(u, v) + \sum_{B \ni u, v} z_B \ge 0 \qquad (\forall (u, v) \in E)\]

Only tight edges (\(\operatorname{slack}(u, v) = 0\)) may enter the alternating tree or be matched, and only tight blossoms (\(z_B > 0 \implies |M \cap E(B)| = \frac{|B|-1}{2}\)) may remain contracted. When the alternating BFS gets stuck, we adjust potentials by \(\Delta = \min(\Delta_1, \Delta_2, \Delta_3, \Delta_4)\):

  • \(y_v \gets y_v - \Delta\) for outer vertices (vis[v] == 1) and \(y_v \gets y_v + \Delta\) for inner vertices (vis[v] == 2);
  • \(z_B \gets z_B + 2\Delta\) for outer root blossoms (vis[B] == 1) and \(z_B \gets z_B - 2\Delta\) for inner root blossoms (vis[B] == 2)!
  • Why Inner Blossom Expansion (\(\Delta_4 = \min_{\text{vis}[B]=2} z_B / 2\)) Is Mandatory: When an inner blossom \(B\)’s dual variable hits \(z_B = 0\), the odd-set constraint on \(B\) is no longer tight; we must expand (拆花) \(B\) back into its constituent sub-blossoms along its even alternating arc so its internal vertices can be re-explored independently.

4.4 The Randomized Skew-Symmetric Tutte Matrix \(T(G)\) & Pfaffian Oracles

When \(N \le 500\) and a problem asks not for a single matching, but to classify all \(M\) edges into Feasible (可行边) and Essential (必须边) matching edges (Problem #175) or to find a Maximum-Weight Matching Matroid Basis (CF Gym 102155 J), running Blossom \(M\) times takes \(O(M \cdot N^3) = O(N^5)\), which TLEs. The Tutte Matrix solves all \(M\) queries simultaneously in a single \(O(N^3)\) matrix inversion!

Define the \(N \times N\) Skew-Symmetric Tutte Matrix \(T(G)\) over a large prime field \(\mathbb{F}_p\) (\(p = 998244353\)) by assigning an independent uniform random variable \(x_{u,v} \in \{1, \dots, p-1\}\) to each edge \(\{u, v\} \in E\) (\(u < v\)):

\[T_{u,v} = \begin{cases} +x_{u,v} & \text{if } \{u, v\} \in E \text{ and } u < v, \\ -x_{v,u} & \text{if } \{u, v\} \in E \text{ and } u > v, \\ 0 & \text{if } \{u, v\} \notin E. \end{cases}\]

ImportantTheorem 22.4 (Tutte’s Theorem, Pfaffian Factorization & Inverse Oracle)

  1. Why Odd Cycles Cancel Identically: In the Leibniz expansion \(\det T(G) = \sum_{\sigma \in S_N} \operatorname{sgn}(\sigma) \prod_{i=1}^N T_{i, \sigma(i)}\), decompose each permutation \(\sigma\) into disjoint cycles. If \(\sigma\) contains any odd-length cycle \(C = (v_1 \to v_2 \to \dots \to v_{2k+1} \to v_1)\), reversing the first odd cycle \(C \mapsto C^{-1}\) preserves \(\operatorname{sgn}(\sigma)\) while multiplying \(\prod_{e \in C} T_e\) by \((-1)^{2k+1} = -1\)! Thus all permutations containing at least one odd cycle cancel in pairs, and \(\det T(G) = (\operatorname{Pf} T(G))^2\), where the Pfaffian sums exclusively over perfect matchings \(M \in \mathcal{M}_{\text{perf}}(G)\):

    \[\operatorname{Pf} T(G) = \sum_{M \in \mathcal{M}_{\text{perf}}(G)} \operatorname{sgn}(M) \prod_{\{u, v\} \in M} x_{u, v}\]

  2. Rank & Maximum Matching: For any general graph \(G\), \(\operatorname{rank}(T(G)) = 2\nu(G)\) with probability \(\ge 1 - \frac{N}{p}\) by the Schwartz–Zippel Lemma.

  3. Universal Reduction to Perfect Matching via \(d = N - 2\nu(G)\) Dummy Vertices: Adding \(d = N - 2\nu(G)\) universal dummy vertices \(w_1, \dots, w_d\) connected to all original vertices \(v \in V\) produces an \((N+d) \times (N+d)\) invertible skew-symmetric matrix \(\hat{T}\) whose perfect matchings correspond precisely to maximum matchings of \(G\) (each covering the \(d\) exposed original vertices with the \(d\) universal dummies!).

  4. All-Edges Feasible & Essential Classification via \(B = \hat{T}^{-1}\): Let \(B = \hat{T}^{-1} \pmod p\). For any original edge \(e = (u, v) \in E\):

    • Feasible Edge (可行边, belongs to AT LEAST ONE maximum matching): By Jacobi’s cofactor identity \(\operatorname{Pf}(\hat{T}_{\setminus \{u,v\}}) = \pm B_{u,v} \operatorname{Pf}(\hat{T})\), edge \((u, v)\) belongs to at least one maximum matching of \(G\) if and only if:

      \[B_{u, v} \not\equiv 0 \pmod p\]

    • Essential Edge (必须边, belongs to EVERY maximum matching): Deleting edge \((u, v)\) from \(G\) is a rank-2 update \(\hat{T}' = \hat{T} - T_{u,v}(e_u e_v^\top - e_v e_u^\top)\). By the Matrix Determinant Lemma, \(\det(\hat{T}') = \det(\hat{T}) \cdot (1 - T_{u,v} B_{v,u})^2\). Hence deleting \((u, v)\) destroys all maximum matchings (\(\det(\hat{T}') = 0\)) if and only if:

      \[T_{u, v} \cdot B_{v, u} \equiv 1 \pmod p \quad \Longleftrightarrow \quad -T_{u, v} \cdot B_{u, v} \equiv 1 \pmod p\]

struct BlossomSolver {
    int n, timer = 0;
    vector<vector<int>> adj;
    vector<int> match, pre, vis, orig, tim;
    queue<int> q;

    BlossomSolver(int n) : n(n), adj(n + 1), match(n + 1, 0),
        pre(n + 1, 0), vis(n + 1, 0), orig(n + 1, 0), tim(n + 1, 0) {}

    void add_edge(int u, int v) {
        adj[u].push_back(v);
        adj[v].push_back(u);
    }

    int find_orig(int x) {
        return orig[x] == x ? x : orig[x] = find_orig(orig[x]);
    }

    int lca(int u, int v) {
        ++timer;
        u = find_orig(u); v = find_orig(v);
        while (tim[u] != timer) {
            tim[u] = timer;
            u = find_orig(pre[match[u]]);
            if (v) swap(u, v);
        }
        return u;
    }

    void contract(int u, int v, int b) {
        int x = u, y = v;
        while (find_orig(x) != b) {
            pre[x] = y;
            y = match[x];
            if (vis[y] == 2) { vis[y] = 1; q.push(y); }
            orig[x] = orig[y] = b;
            x = pre[y];
        }
    }

    void augment(int v) {
        while (v) {
            int pv = pre[v], nv = match[pv];
            match[v] = pv; match[pv] = v;
            v = nv;
        }
    }

    bool bfs(int root) {
        fill(vis.begin(), vis.end(), 0);
        fill(pre.begin(), pre.end(), 0);
        iota(orig.begin(), orig.end(), 0);
        while (!q.empty()) q.pop();
        q.push(root); vis[root] = 1;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int v : adj[u]) {
                if (find_orig(u) == find_orig(v) || vis[v] == 2) continue;
                if (!vis[v]) {
                    vis[v] = 2; pre[v] = u;
                    if (!match[v]) { augment(v); return true; }
                    vis[match[v]] = 1; q.push(match[v]);
                } else {
                    int b = lca(u, v);
                    contract(u, v, b); contract(v, u, b);
                }
            }
        }
        return false;
    }

    int solve() {
        int ans = 0;
        for (int i = 1; i <= n; ++i)
            if (!match[i] && bfs(i)) ++ans;
        return ans;
    }
};

Problem #170 (SS-2): [BZOJ 3218 / Luogu P3218] a + b Problem

Judge Links: Luogu P3218 / BZOJ 3218 Constraints: \(N \le 5000\), \(0 \le a_i, l_i, r_i \le 10^9\), \(0 \le b_i, w_i, p_i \le 10^5\), Time Limit \(2.0\text{ s}\).

Step 1: Non-Graph Diagnostic Signal

Binary choices with a bundled implication penalty scream Chapter 09 Project Selection Min-Cut, and the 2D prefix-range predicate \(\{j < i : l_i \le a_j \le r_i\}\) requires a Prefix Persistent Segment Tree (主席树).

Step 2: Intermediate Algebraic / Logical Representation

Let \(x_i \in \{0, 1\}\) be \(1\) if cell \(i\) is painted Black (\(i \in S\)) and \(0\) if White (\(i \in T\)). Starting from the ideal reward \(\sum_{i=1}^N (b_i + w_i)\), we minimize the lost reward plus penalties by introducing a binary penalty indicator \(z_i \in \{0, 1\}\) for each cell \(i\):

\[\min_{x, z \in \{0, 1\}^N} \sum_{i=1}^N \Big[ w_i (1 - x_i) + b_i x_i + p_i x_i (1 - z_i) + \sum_{\substack{1 \le j < i \\ l_i \le a_j \le r_i}} \infty \cdot z_i (1 - x_j) \Big]\]

Check the logic: if cell \(i\) is Black (\(x_i = 1\)) and sets \(z_i = 1\) to avoid paying \(p_i\), then the \(\infty\)-penalty forces \(x_j = 1\) (Black) for every \(j < i\) with \(a_j \in [l_i, r_i]\). If any such \(j\) is White (\(x_j = 0\)), we are forced to set \(z_i = 0\) and pay \(p_i\)!

Problem #175 (Mas-1): All-Edges Matching Classification (可行边 & 必须边) & Matching Matroid Basis (CF Gym 102155 J / Tutte Pfaffian Oracle)

Judge Link: CF Gym 102155 Problem J (Choosing Subsets) Constraints: \(N \le 500\), \(M \le \binom{N}{2}\), Vertex weights \(w_v \le 10^9\), Time Limit \(2.0\text{ s}\).

Step 1: Non-Graph Diagnostic Signal

Given a general non-bipartite graph \(G = (V, E)\) with \(N \le 500\), we must either:

  1. Task A (All-Edges Classification): Determine for every edge \(e = (u, v) \in E\) whether \(e\) belongs to at least one maximum matching (可行边) and whether \(e\) belongs to every maximum matching (必须边).
  2. Task B (CF Gym 102155 J, Matching Matroid Basis): Find a maximum-matching-saturable subset of vertices \(S \subseteq V\) of maximum total vertex weight \(\sum_{v \in S} w_v\).

Both tasks require algebraic reasoning on the Skew-Symmetric Tutte Matrix \(T(G)\) (Theorem 22.4) in \(O(N^3)\) time over \(\mathbb{F}_{998244353}\).

Step 2: Intermediate Algebraic / Logical Representation

Let \(T(G)\) be the \(N \times N\) skew-symmetric Tutte matrix with random \(x_{u,v} \in \mathbb{F}_p^\times\).

  • For Task B (Matching Matroid): By Tutte’s Theorem, a subset \(S \subseteq V\) can be covered by some matching of \(G\) iff the row space of \(T(G)[S, V]\) has full rank \(|S|\) — that is, the rows of \(T(G)\) form a linear matroid over \(\mathbb{F}_p\) that represents the Matching Matroid! Therefore, we simply sort the vertices \(v_1, \dots, v_N\) in descending order of weight \(w_v\) and maintain a Linear Basis (Gaussian Elimination) over the rows of \(T(G)\), greedily inserting row \(T_{v_i, *}\) if it is linearly independent of previously chosen rows!
  • For Task A (Feasible & Essential Edges): Let \(r = \operatorname{rank}(T(G)) = 2\nu(G)\). Pad \(T(G)\) with \(d = N - r\) universal dummy vertices \(w_1, \dots, w_d\) connected to all \(v \in V\) with random weights to form an invertible \((N+d) \times (N+d)\) skew-symmetric matrix \(\hat{T}\), and compute \(B = \hat{T}^{-1} \pmod p\). Then:
    • \((u, v)\) is Feasible (可行边) \(\iff B_{u,v} \not\equiv 0 \pmod p\);

const int MOD = 998244353;
long long qpow(long long a, long long b = MOD - 2) {
    long long r = 1;
    for (; b; b >>= 1, a = a * a % MOD) if (b & 1) r = r * a % MOD;
    return r;
}

// Invert K x K matrix A mod 998244353; returns rank and writes A^{-1} into invA
int invert_matrix(vector<vector<int>> A, vector<vector<int>> &invA) {
    int K = A.size();
    invA.assign(K, vector<int>(K, 0));
    for (int i = 0; i < K; ++i) invA[i][i] = 1;
    int rank = 0;
    for (int col = 0; col < K; ++col) {
        int piv = -1;
        for (int row = rank; row < K; ++row)
            if (A[row][col]) { piv = row; break; }
        if (piv == -1) continue;
        swap(A[rank], A[piv]); swap(invA[rank], invA[piv]);
        long long inv_p = qpow(A[rank][col]);
        for (int j = 0; j < K; ++j) {
            A[rank][j] = A[rank][j] * inv_p % MOD;
            invA[rank][j] = invA[rank][j] * inv_p % MOD;
        }
        for (int row = 0; row < K; ++row) if (row != rank && A[row][col]) {
            long long factor = A[row][col];
            for (int j = 0; j < K; ++j) {
                A[row][j] = (A[row][j] - factor * A[rank][j]) % MOD;
                if (A[row][j] < 0) A[row][j] += MOD;
                invA[row][j] = (invA[row][j] - factor * invA[rank][j]) % MOD;
                if (invA[row][j] < 0) invA[row][j] += MOD;
            }
        }
        ++rank;
    }
    return rank;
}

void build_manhattan_hubs(int N, MCMF &mcmf, int S, int T) {

7. Pre-Submission Checklist (FM-22 & H-22 Audit)

Before submitting any Data-Structure-Accelerated Flow Graph or Non-Bipartite Matching solution, verify all six invariants:

  1. In-Tree vs. Out-Tree Separation (H-22): Did you keep \(\mathcal{T}_{\text{in}}\) (bottom-up: \(lc, rc \to p\)) and \(\mathcal{T}_{\text{out}}\) (top-down: \(p \to lc, rc\)) as strictly separate node sets? Never make a single segment tree bidirectional!
  2. Capacity Placement (FM-22): Are all internal edges inside your Segment Tree, Persistent Segment Tree, KD-Tree, or Binary Lifting table set to capacity \(\infty\) and cost \(0\)? Finite capacities \(c_k\) and costs \(w_k\) belong exclusively on the unique query bridge \(b_{\text{in}, k} \xrightarrow{c_k, w_k} b_{\text{out}, k}\) or on the \(N\) leaf edges!
  3. Duplicate-Key Leaf Chaining (主席树): In insert_pst(u, prev, ...), did you connect dinic.add_edge(u, prev, INF) so earlier items with identical coordinate-compressed keys are never orphaned?
  4. 4-Sign Manhattan Direction: Are you maximizing \(|x_1 - x_2| + |y_1 - y_2|\)? Remember that 4-Sign Hubs only work for \(\max\); for minimizing \(|a_i - a_j|\) with \(j < i\), use CDQ + 1D Bi-Directional Sorted Value Chain (#172).
  5. Blossom Bridge & Two-Phase Ordering: In Edmonds’ Blossom contract(u, v, b), did you set pre[x] = y before advancing y = match[x]? And in vertex-splitting step gadgets (#173), did you augment mandatory ball vertices before optional internal basket edges?
  6. Tutte Dummy Padding: Before inverting \(T(G)\) to classify feasible/essential edges (#175), did you pad \(T(G)\) with \(d = N - 2\nu(G)\) universal dummy vertices so \(\hat{T}\) has full rank \(N + d\)?
