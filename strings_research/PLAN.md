## 1. Goal Description & Core Pedagogical Shift (Why Advanced Strings Require a Structural-Invariant Architecture)

This project creates a fourth standalone competitive programming textbook (`/home/maomao90/Documents/IO/ICPC-math-notes/strings/`) and research database (`/home/maomao90/Documents/IO/ICPC-math-notes/strings_research/`) dedicated to **Advanced String Algorithms, Structural Periodicity & Border Theory, Lyndon Factorization & the Runs Theorem, Advanced Suffix/Palindrome Structures & Data-Structure Coupling, Internal Pattern Matching (IPM), Algebraic/FFT String Matching, Goulden–Jackson & Automaton Generating Functions, Tiskin's Seaweed Matrices (Unit-Monge Algebra), Word Equations, and Combinatorics on Words**, built to the exact same standard of depth, multi-agent redundancy, and mathematical rigor as `fps_research/` and `flows_research/`.

### Prerequisite Boundary (What Is Assumed vs. What This Textbook Teaches)

Per the project's editorial policy (`AGENTS.md`) and scope definition:
- **Assumed Reader Baseline**: The reader is **already fluent** in basic-to-intermediate string machinery and holds tested library implementations of **Polynomial Rolling Hash**, **KMP (`pi` array)**, **Z-Algorithm**, **Trie**, **Aho–Corasick (AC) Automaton**, **Manacher's Algorithm**, **Suffix Array (`SA`, `rk`, `height`/LCP + RMQ)**, **Suffix Automaton (SAM)**, and **Palindromic Tree (Eertree / PAM)**. Standard construction templates for these structures are **never** re-derived from scratch as beginner tutorials or dumped as boilerplate code.
- **Why Advanced String Problems Still Stump Readers Who Know SAM, SA, and PAM**:
  1. **Hidden Combinatorial Sparsity ("Why are there only $O(\log N)$ or $O(N)$ active states?")**: Advanced string algorithms rely on deep structural theorems of Combinatorics on Words—such as the **Weak Periodicity Lemma** (borders of length $\ge |S|/2$ form a single arithmetic progression, partitioning all borders/palindromic suffixes into $O(\log N)$ APs), the **Significant Suffixes Theorem** (only $O(\log N)$ suffixes of $S[1..r]$ can ever become lexicographically minimal after appending a right extension $T$), and the **Runs Theorem** (a string of length $N$ contains strictly fewer than $N$ maximal periodic runs, with $\sum \text{exp}(R) < 3N$). Standard editorials quote these bounds as "well-known facts" without proving *why* two overlapping periods or lexicographical candidates annihilate one another.
  2. **Unmotivated Data-Structure Coupling ("How do you query substrings $S[l..r]$ when SAM/PAM represents prefixes of the whole string $S[1..N]$?")**: A black-box SAM or PAM answers queries about the entire string $S$. Contest problems, however, restrict attention to an arbitrary substring $S[l..r]$, require dynamic/online extensions, or couple two independent structures (e.g., **SAM Link Tree + Segment Tree Merging on $\text{endpos}$ + Binary Lifting**, **SAM/PAM + Link-Cut Tree `access` + Fenwick Tree** for offline range distinct substrings/palindromes, or **PAM `slink` AP-Chain DP**).
  3. **Algebraic & Matrix Reformulations of Non-Linear String Operations**: Modern grandmaster problems replace classical string matching and DP with algebraic engines: **Polynomial / FFT Wildcard & $k$-Mismatch Matching**, **Goulden–Jackson Cluster Method & Martingale PGFs**, **Invertible Subsequence Automaton Matrices**, **Tiskin's Seaweed Matrices (Unit-Monge Braid Multiplication) for All-Pairs Interval LCS**, and **Homomorphic Non-Abelian Group Hashing ($SL_2(\mathbb{F}_p)$)** for stack-cancellation languages.

## 2. Key Design Decisions & Editorial Standards

> [!IMPORTANT]
> **1. The "Zero Magic Invariants & Structural Decompositions" Mandate (4-Step String Derivation)**
> The textbook and research files must **never** quote a structural theorem ("Borders form $O(\log N)$ arithmetic progressions", "Maintain two DP values per `slink` chain", "Build the Seaweed Matrix", or "LCT `access` updates the last occurrence") as a black-box recipe. Every advanced technique and every worked/practice problem solution must explicitly walk through four steps:
> 1. **The Diagnostic Signal (Why Naive String Structures Fail)**: What exact feature in the problem statement and constraints—such as arbitrary substring queries $S[l..r]$ (`[NOI2018] 你的名字`), partitioning into palindromes/squares (`CF 932G`), lexicographical comparison under right-extension (`[ZJOI2017] 字符串`), all-pairs interval LCS (`[THUPC 2021]`), or approximate matching with wildcards/mismatches—causes standard whole-string SAM/SA/PAM/KMP to take $O(N^2)$ time or $O(N^2)$ memory?
> 2. **The Combinatorial Word Invariant (Double-Overlap / Periodicity / Monge Proof)**: Before introducing any data structure, prove the underlying word-combinatorial property using concrete alignment diagrams and index equalities:
>    - *For Border/Palindrome APs*: Show that if $|u|, |v| \ge |S|/2$ are borders of $S$, their overlap has length $\ge |u| + |v| - |S| \ge 0$, forcing $S$ to be periodic with period $d = |S| - |u|$ and locking all borders of length $\ge |S|/2$ into a single arithmetic progression of step $d$.
>    - *For Significant Suffixes*: Show that if $u$ and $v$ ($|u| < |v| < 2|u|$) are both candidate minimal suffixes of $S[1..r]$ under right-extensions, then $u$ is a border of $v$, inducing a tandem repeat $v = w^k u'$ where one of $u, v$ is strictly dominated for *every* right extension $T$.
>    - *For Runs & Lyndon Roots*: Show why every run $R = [l, r, p]$ contains a unique Lyndon root of length $p$ under either $<$ or $>$ alphabet order, immediately bounding the number of runs by the number of Lyndon tree nodes ($< N$).
>    - *For Substring Queries on SAM ($\text{endpos}$ Clipping)*: Show why $S[l..r]$ occurs in node $u$ of the SAM of $T$ if and only if $\text{endpos}_T(u) \cap [l' + |S[l..r]| - 1, r'] \ne \emptyset$—reducing a variable-length string containment check to a 1D point-in-interval query on a Segment Tree Merge!
> 3. **The Reverse-Engineering Scratchpad (Algorithmic & Data-Structure Compilation)**: Derive the exact state transition, rolling DP offset, LCT color-segment invariant, or polynomial convolution formula step-by-step from what changes when advancing from $r-1 \to r$ (or merging child subtrees in the Link Tree).
> 4. **Boundary Pitfalls & Broken-Invariant Counterexamples**: Explicitly exhibit small strings (often Fibonacci/Sturmian words like `abaababa` or `aaaaab`) that break naive shortcuts—e.g., why forgetting the condition $\text{pos} - \text{len}(u) + 1 \ge l$ when querying $\text{endpos}(u)$ counts substrings that start *before* $l$; why PAM `slink` DP fails if you do not understand why the shifted AP covers all but one new element at $r-1$; why Generalized SAM online insertion creates zero-length clone bugs if existing transitions are not split properly; and why naive Deque PAM fail-chain traversal degrades to $O(N)$ per step without direct transition tables (`quick_link`).

> [!IMPORTANT]
> **2. Per-Topic Smooth Difficulty Ladders + Blind Topic-Group Checkpoints + Reserve Archive**
> - **Per-Topic Smooth Difficulty Curve**: Every independent chapter has its own curated problem set ordered along a smooth 4-tier ramp (`Stepping Stone` $\to$ `Intermediate` $\to$ `Advanced` $\to$ `Mastery`).
> - **Blind Topic-Group Checkpoints (`CP-I`–`CP-X`, No Topic Spoilers)**: Because knowing whether a string problem requires SAM + Segment Tree Merge, Runs Enumeration, Lyndon Significant Suffixes, or FFT Wildcard Matching gives away the core reduction, each Part concludes with a **Blind Checkpoint Problem Set** where the required technique is hidden in the visible text. Hint 1 teaches how to diagnose the right structural tool from the constraints and query types alone; Hint 2 reveals the combinatorial invariant; Hint 3 guides the data-structure/algebraic assembly; and the Solution gives the complete derivation.
> - **Strict Quarantine of Pure Template Problems**: Library Checker (`Suffix Array`, `Z Algorithm`, `Number of Substrings`, `Enumerate Palindromes`, `Run Enumerate`, `Lyndon Factorization`, `Wildcard Pattern Matching`) and bare Luogu `【模板】` problems are strictly excluded from textbook chapters and logged in a quarantine table (`R-01..R-XX`).

> [!IMPORTANT]
> **3. Zero-Friction Inline Problem Presentation & Full Multilingual Citations**
> - Every textbook problem (both per-chapter ladder and blind checkpoint problems) includes a **concise, self-contained mathematical problem statement and exact constraints** (string length $N, Q \le \dots$, alphabet size $|\Sigma|$, time/memory limits, online vs. offline requirement) directly inside the `.qmd` file, followed by progressive collapsible hints and a collapsible **Complete Derivation & Solution**.

> [!IMPORTANT]
> **4. Post-Research Corpus-Driven Textbook Restructuring (No Fixed Pre-Research Outline)**
