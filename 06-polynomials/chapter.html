06 — Fast Polynomial Algorithms

A polynomial is a DP table that knows how to merge

Here is a familiar situation. You have a DP array f[k] = number of ways to reach total size \(k\) using the first group of items, and g[k] for the second group. Combining the groups means

\[h[k] = \sum_{i+j=k} f[i]\,g[j],\]

which is \(\Theta(n^2)\) if you write the double loop — and is exactly polynomial multiplication if you call f and g polynomials. Doing it in \(O(n\log n)\) instead is often the entire difficulty of a problem.

That is the point of view of this chapter: a polynomial is a compact description of size-indexed choices, \([x^k]A(x)\) is the answer at total size \(k\), and multiplication is “split a total between two independent parts”. Once you see convolution in a merge, a dozen fast operations become available — evaluation at many points, division, shifting the variable, multiplying thousands of small factors — and each one has an algebraic precondition that quietly decides whether your submission is correct.

We assume your library already contains a tested convolution routine. What this chapter supplies is why the operations work and when they are legal.

Prerequisites, notation, and learning objectives

Read fields and modular units and counting products.

You should finish able to justify transform-based multiplication, prove the division/remainder invariant, recover a polynomial from samples, recognize a correlation or a shift hiding in a statement, and state the exact condition each of those needs.

Write \(A(x) = \sum_{i=0}^{a}a_i x^i\) with coefficients in a commutative ring \(R\). The degree is the largest index with a nonzero coefficient; we use \(\deg 0 = -\infty\) when comparing. Polynomial equality means coefficientwise equality — not equality as functions, a distinction that bites over finite fields, where \(x^p - x\) vanishes at every point of \(\mathbb F_p\) without being the zero polynomial.

Let \(M(n)\) be the number of ring operations to multiply polynomials with at most \(n\) coefficients; \(M(n) = O(n\log n)\) for FFT-friendly settings. All complexity claims assume \(M(n)/n\) is nondecreasing and that costs over doubling sizes sum to \(O(M(n))\), which holds for schoolbook and FFT multiplication alike. Ring operations cost \(1\); integer bit complexity is a separate accounting.

1. Multiplication by evaluation

For \(C = AB\),

\[c_k = \sum_{i+j=k}a_ib_j. \tag{1}\]

Each summand takes an \(i\)-sized object from \(A\) and a \((k-i)\)-sized object from \(B\). That “split a total” reading is why convolution shows up in counting, DP merging, and formal power series.

The fast algorithm rests on one observation: at any point \(z\), \((AB)(z) = A(z)B(z)\). In value form multiplication is pointwise and linear-time. So: evaluate both polynomials at a well-chosen set of points, multiply the values, and interpolate back. The whole trick is choosing points at which evaluation and interpolation are themselves fast. FFT uses complex roots of unity; NTT uses roots of unity inside a finite field.

Why roots of unity, exactly

Work over a field containing a primitive \(L\)-th root of unity \(w\) — meaning \(w^L = 1\) and \(w^d \ne 1\) for \(1 \le d < L\) — with \(L\) invertible. The one fact everything follows from is

\[\sum_{j=0}^{L-1}w^{jt} = \begin{cases}L, & L \mid t,\\ 0, & L \nmid t.\end{cases}\]

Why the second case: multiply the sum by \(1 - w^t\); it telescopes to \(1 - w^{Lt} = 0\), and \(1 - w^t\) is a nonzero field element, hence invertible, so the sum is \(0\).

With \(\widehat a_j = A(w^j)\) and \(\deg A < L\), this gives the inversion formula

\[\frac1L\sum_{j=0}^{L-1}\widehat a_j w^{-jk} = \sum_{i=0}^{L-1}a_i\left(\frac1L\sum_{j=0}^{L-1}w^{j(i-k)}\right) = a_k .\]

Each coefficient survives only at its matching frequency, and everything else cancels. So evaluation at the \(L\) powers of \(w\) is an invertible change of representation — and its inverse is the same computation with \(w^{-1}\) plus a final scaling by \(L^{-1}\).

It is also fast when \(L\) is a power of two. Split by parity of index, \(A(x) = A_e(x^2) + x A_o(x^2)\). The squares \(w^{2j}\) take only \(L/2\) distinct values, so both halves are the same problem at half the size, and the pair \(w^j, w^{j+L/2}\) combines the two recursive values with opposite signs. Every coefficient lands in exactly one child, so nothing is lost or duplicated: \(T(L) = 2T(L/2) + O(L) = O(L\log L)\).

NoteA transform you can check by hand

Over \(\mathbb F_{17}\), \(w = 4\) has order \(4\) (\(4^2 = 16\), \(4^4 = 1\)). The points are \(1, 4, 16, 13\), and \(1+2x\) evaluates to \(3, 9, 16, 10\). Running the inverse formula returns \((1,2,0,0)\) — exactly, with no rounding, which is the practical reason NTT is preferred over complex FFT when the answer is modular.

The transform contract

For an NTT of length \(L = 2^s\) modulo a prime \(p\):

  • Root exists: \(L \mid p - 1\), so that \(\mathbb F_p^\times\) (cyclic of order \(p-1\)) contains an element of order \(L\). This is why \(998244353 = 119\cdot 2^{23} + 1\) is the contest favourite: it supports every power of two up to \(2^{23}\).
  • Length is enough: \(L \ge |A| + |B| - 1\), covering every possible output degree.

If the required modulus \(m\) is not NTT-friendly, do not pretend a single transform computes the answer. Convolve modulo one or more NTT primes, reconstruct the true integer coefficient by CRT (or use Garner to produce it directly modulo \(m\) without materializing a huge integer), then reduce. Garner saves memory; it does not remove the range requirement. For signed coefficients, centered CRT must also decide whether a representative means \(c\) or \(c - P\), where \(P\) is the product of the auxiliary primes, and a Garner residue needs the matching sign correction modulo \(m\).

The number of primes is decided by a proved bound on the integer coefficients: a signed coefficient bounded by \(B\) in absolute value needs a modulus product exceeding \(2B\). “Three primes” is a convention, not a proof. Complex FFT needs coefficient splitting plus a rounding-error bound instead.

Worked failure: forgetting to pad

Take \(A = B = 1 + x\), so \(AB = 1 + 2x + x^2\). Run a length-\(2\) transform: the points are the roots of \(x^2 = 1\), and the result comes back as \(2 + 2x\). The \(x^2\) coefficient wrapped around into the constant term.

The reason is worth remembering: evaluation at the \(L\)-th roots of unity computes the product in \(R[x]/(x^L - 1)\), i.e. a cyclic convolution. It equals the ordinary product only when \(\deg(AB) < L\). Pad accordingly, and handle empty inputs by returning the zero polynomial before choosing \(L\).

2. Division: reverse the polynomial, invert a series

Assume \(B \ne 0\) with a unit leading coefficient. Given \(A\), we want \(A = BQ + R\) with \(\deg R < \deg B\). (Degenerate cases: \(A = 0\) gives \(Q = R = 0\); \(\deg A < \deg B\) gives \(Q = 0\), \(R = A\); a unit constant divisor gives \(R = 0\).)

Long division peels off the highest-degree term repeatedly, which is inherently sequential. The trick is to reverse the coefficient arrays: the highest-degree end becomes the low-degree end of a power series, and low-degree work is where fast inversion lives.

Let \(k = \deg A - \deg B + 1\) (the number of quotient coefficients), and let \(\operatorname{rev}_k(F)\) read \(F\) from its leading coefficient downward, keeping \(k\) coefficients. Then

\[\operatorname{rev}_k(Q) \equiv \operatorname{rev}_k(A)\operatorname{rev}_k(B)^{-1} \pmod{x^k}. \tag{2}\]

Two things make this legal. First, reversal turns the leading coefficient of \(B\) into the constant coefficient of \(\operatorname{rev}_k(B)\), and a power series is invertible exactly when its constant term is a unit — which is the hypothesis on \(B\). Second, the remainder \(R\) has low degree, so after reversal it sits beyond the first \(k\) coefficients and vanishes modulo \(x^k\). Reverse the result back to get \(Q\), then \(R = A - BQ\).

NoteHand-worked division

\(A = x^3 + 2x + 1\), \(B = x + 1\), so \(k = 3\). Reversed prefixes: \(\operatorname{rev}_3(A) = 1 + 2x^2\) and \(\operatorname{rev}_3(B) = 1 + x\). Modulo \(x^3\), \((1+x)^{-1} = 1 - x + x^2\), so

\[\operatorname{rev}_3(Q) = (1 + 2x^2)(1 - x + x^2) \equiv 1 - x + 3x^2 .\]

Reversing gives \(Q = x^2 - x + 3\), and \(R = A - BQ = -2\). Check: \((x+1)(x^2-x+3) - 2 = x^3 + 2x + 1\). ✓

Cost is \(O(M(n))\) with fast multiplication and fast series inversion (derived in formal power series; the geometric series sufficed above). Over a general ring the unit-leading-coefficient hypothesis is real: modulo a composite number, a nonzero leading coefficient may still be non-invertible and the whole contract collapses.

3. Product trees and multipoint evaluation

Evaluating \(f\) at \(m\) points costs \(O(nm)\) by Horner. To do better, reuse the remainder identity: \(f \bmod (x - x_i)\) is the constant \(f(x_i)\).

Build a balanced binary tree over the points. A leaf holds \(x - x_i\); an internal node holds the product of its children,

\[P_v(x) = \prod_{i \text{ below } v}(x - x_i).\]

Reduce \(f\) modulo the root product, then push each remainder down: at a child, reduce again modulo that child’s product. Every leaf ends up holding \(f \bmod (x - x_i) = f(x_i)\). It is the segment-tree idea with “the polynomial vanishing on this interval of points” stored at each node — and correctness is just the fact that reducing modulo a product and then modulo a factor is the same as reducing modulo the factor.

With \(\deg f = O(m)\) and a balanced tree, the divisions cost \(O(M(m)\log m)\) total. A higher-degree \(f\) pays an extra division at the root. For few points, Horner is simpler and usually faster — use the tree only when the asymptotics actually matter.

4. Interpolation reverses evaluation

Given \(m\) samples, we want a polynomial of degree less than \(m\). That degree bound is not a stylistic choice: adding any multiple of \(\prod_i(x - x_i)\) leaves every sample unchanged, so without the bound there are infinitely many answers.

Assume the \(x_i\) are pairwise distinct and set \(P(x) = \prod_i(x - x_i)\). The polynomial \(P(x)/(x - x_i)\) vanishes at every sample point except \(x_i\), where it takes the value \(P'(x_i)\). Dividing by that gives a basis polynomial which is \(1\) at \(x_i\) and \(0\) elsewhere, so

\[f(x) = \sum_i y_i\,\frac{P(x)}{(x - x_i)\,P'(x_i)} . \tag{3}\]

There is nothing magical here — each summand is responsible for exactly one sample and invisible at the others.

To compute it fast: get all \(P'(x_i)\) by multipoint evaluation, put \(w_i = y_i / P'(x_i)\) at the leaves of the same product tree, and merge with

\[F_v = F_L P_R + F_R P_L .\]

The invariant is that \(F_v\) equals the sum, over leaves \(i\) below \(v\), of \(w_i \prod_{j \text{ below } v,\, j \ne i}(x - x_j)\): a left-subtree term is missing exactly the right product, and vice versa, so nothing is dropped or double-counted. The root is (3), at cost \(O(M(n)\log n)\).

Uniqueness. Over a field with distinct points, a nonzero polynomial of degree \(< m\) cannot vanish at \(m\) points, since dividing out each root factor would force the degree up to \(m\). So (3) is the answer, not an answer. Over a general ring, require every difference \(x_i - x_j\) to be a unit.

Repeated points break it: \(P'(x_i) = 0\) and (3) is undefined. Duplicate samples with equal values can be deduplicated; contradictory values have no solution at all. Prescribing derivatives at repeated points is Hermite interpolation, a different contract.

The common special case. For values at the consecutive points \(0, 1, \ldots, n\), the denominators collapse to \(i!\,(-1)^{n-i}(n-i)!\), and prefix/suffix products of \((t - j)\) evaluate (3) at a single arbitrary \(t\) in \(O(n)\). This is the standard way to jump to a huge argument of a polynomial-valued DP — it needs the factorials to be invertible, so normally \(n < p\).

5. Taylor shift: substituting \(x + c\) in one convolution

Sometimes you need the whole coefficient list of \(f(x + c)\), not one value. Expanding each monomial,

\[[x^k]f(x+c) = \sum_{i \ge k}a_i\binom ik c^{\,i-k}. \tag{4}\]

Degree \(i\) feeds every lower degree \(k\), and the coupling depends only on \(i - k\) — which is the signature of a convolution, once the binomial coefficient is broken into factorials.

Put \(u_{n-i} = a_i\,i!\) (note the reversal, which turns \(i - k\) into a convolution index) and \(v_j = c^{\,j}/j!\) with \(n = \deg f\). Then

\[\frac{(u * v)_{n-k}}{k!} = \sum_{i \ge k}a_i\binom ik c^{\,i-k},\]

so one convolution plus a final division by \(k!\) produces every shifted coefficient. Only terms with \(k \le i \le n\) contribute to output index \(n - k\), so the index ranges take care of themselves.

Check: \(f(x) = x^2\), \(c = 1\). The convolution entries at indices \(2,1,0\) are \(1, 2, 2\); dividing by \(0!, 1!, 2!\) gives \(1, 2, 1\), the coefficients of \((x+1)^2\). Larger check: \(f = 1 + 3x + 2x^2\) with \(c = 2\) gives \(15 + 11x + 2x^2\), which you can confirm by direct substitution.

As with the binomial transform of Chapter 03, this needs factorials through the working degree to be units — in practice, a prime modulus larger than the degree.

6. Multiplying many factors: keep the merges balanced

Computing \(\prod_i A_i(x)\) left to right is a trap: a huge accumulated product is repeatedly multiplied by a tiny factor, so the cost is quadratic in the total degree.

Merge with a divide-and-conquer tree instead — or with a priority queue that always combines the two smallest current degrees. For \(k\) factors of positive degree and total degree \(N\), a tree balanced by factor count has \(\lceil \log_2 k\rceil\) levels, each holding total degree at most \(N\), for \(O(M(N)\log(k+1))\) overall. Degree-balanced merging usually wins when factor sizes vary a lot. Absorb constant factors separately in \(O(k)\), and short-circuit if any factor is zero.

If the question only asks for coefficients through degree \(D\), truncate after every merge. In a knapsack-style product like \(\prod_i(1 + x^{w_i})\), a coefficient above \(D\) can never influence a coefficient at or below \(D\) later, so keeping it wastes both time and memory.

7. Worked contest translation: all alignments at once

Given a binary text of length \(n\) and a pattern of length \(m \le n\), compute the Hamming distance at every start position \(0 \le s \le n - m\). Naively \(O(nm)\); one convolution suffices.

The obstacle is that convolution pairs indices summing to a constant, whereas alignment pairs indices with a constant difference. Reversing one array converts one into the other. Let \(a_i = [\text{text}_i = 1]\) and \(b_{m-1-j} = [\text{pattern}_j = 1]\). Then

\[[x^{s+m-1}]A(x)B(x) = \sum_{j=0}^{m-1}a_{s+j}\,[\text{pattern}_j = 1],\]

because \(i + (m-1-j) = s + m - 1\) forces exactly \(i = s + j\). That coefficient counts the aligned \((1,1)\) pairs. With \(u_s\) the number of ones in the text window and \(v\) the number in the pattern, the mismatch count is

\[u_s + v - 2\,[x^{s+m-1}]AB,\]

since positions counted in both \(u_s\) and \(v\) are precisely the aligned one-one pairs, and everything else contributes one mismatch. Prefix sums give all \(u_s\) in linear time.

Check: text 10110, pattern 110. The correlations are \((1,1,2)\) and the distances \((2,2,0)\) — the last window matches exactly. Cost: \(O(M(n+m))\) time, linear memory, with the coefficient range needing to reach only \(m\).

8. Failure checklist and reference

  • Before an NTT: check both the padded length and the root-of-unity condition on the modulus.
  • Before a series inverse: check the constant term is a unit. Before a division: check the leading coefficient instead — different condition.
  • Normalize negative coefficients into the target ring.
  • For CRT-based convolution: prove the reconstruction range actually covers the largest possible coefficient.
  • Interpolation needs distinct sample points; the consecutive-point shortcut additionally needs invertible factorials.
  • Verify a small product, a quotient/remainder identity, and a few interpolation samples against a slow routine before trusting the fast one.
Operation Cost Contract
Multiplication \(M(n)\) padded length; exact arithmetic or a rounding bound
Division \(O(M(n))\) nonzero divisor with unit leading coefficient
Multipoint evaluation \(O(M(n)\log n)\) comparable degree and sample count; monic tree divisors
Interpolation \(O(M(n)\log n)\) degree < sample count; unit point differences
One consecutive-point query \(O(n)\) nodes \(0,\ldots,n\); unit factorials
Taylor shift \(O(M(n))\) unit factorials through the degree

The solved exercise sequence tests these contracts through modelling and counterexamples.
