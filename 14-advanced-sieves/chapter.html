14 — Advanced Summatory Sieves

One number, from a table you cannot build

You are asked for \(\sum_{n \le 10^{11}}\varphi(n)\). A linear sieve computes \(\varphi\) for every \(n\) — but \(10^{11}\) values will not fit in memory, and will not finish in time either. The catch is that you were never asked for the table. You were asked for one number.

That distinction is the whole chapter. Whenever a recurrence for the prefix \(F(N) = \sum_{n\le N}f(n)\) only ever refers to itself at arguments of the form \(\lfloor N/i\rfloor\), the recursion touches fewer than \(2\sqrt N\) distinct arguments, because \(\lfloor N/i\rfloor\) takes only that many values. A prefix over \(10^{11}\) terms then costs about \(N^{2/3}\) operations — seconds, not centuries.

So “summatory sieve” never means skipping information by magic. It means: find a recurrence whose arguments close under floor division. Three standard ways to find one, each keyed to a different piece of structure:

  • Du Jiao sieve — an easy Dirichlet convolution \(f * g = h\) isolates \(F(N)\).
  • Min_25 sieve — \(f\) is multiplicative and \(f(p)\) is a low-degree polynomial in \(p\).
  • Powerful-number sieve — subtract off an easy function that agrees with \(f\) on primes; what remains lives only on numbers whose prime exponents are all at least two, and there are only \(O(\sqrt N)\) of those.

Before this chapter, be comfortable with multiplicative functions, Möbius inversion, and quotient grouping from Chapter 02 — this chapter is those ideas pushed until they become algorithms.

Prerequisites and learning objectives

Read multiplicative functions and divisor sums. For weighted prefixes, the discrete-sums chapter supplies polynomial block sums. You should learn to derive a prefix recurrence, prove that its recursive states close under floor division, distinguish a prime-sum sieve from full multiplicative enumeration, and justify a cutoff using the actual time and storage model.

Definitions and notation

\(N\ge1\) is the fixed query bound. An arithmetic function \(f\) has prefix \(F(x)=\sum_{1\le n\le x}f(n)\) for integer \(x\ge0\), with \(F(0)=0\). \(f*g\) means Dirichlet convolution. Coefficients lie in a commutative ring; integer formulas are evaluated exactly before reduction unless their denominators are units. In prime enumeration, \(p_i\) is the \(i\)th prime with zero-based index \(p_0=2\). A cutoff \(B\) is an integer preprocessing bound. Operation counts below treat exact coefficient operations as constant time.

1. The \(O(\sqrt{N})\) quotient-state space

This section is the reason all three methods work, so it is worth pinning down before any of them.

Every recursive call in these methods should normally be one of the distinct values \(\lfloor N/i\rfloor\). This is a small state space because values below \(\sqrt N\) can occur directly, while every value above it equals \(\lfloor N/i\rfloor\) for some \(i<\sqrt N\). There are fewer than \(2\sqrt N\) values in total. Two common indexing schemes are:

  • store large values in a hash map and precompute all values up to a cutoff;
  • map \(v\) to \(v\) itself if \(v≤\sqrt{N}\), otherwise to \(N/v\) in a second array.

For \(N=20\), the distinct states are \(20,10,6,5,4,3,2,1\), rather than twenty different arguments. This is the object being memoized; quotient grouping is what makes a recurrence over all divisors practical.

Never accidentally memoize arbitrary arguments: that can turn an intended \(O(\sqrt{N})\) state set into linear space.

Closure follows from the identity \(\lfloor\lfloor N/a\rfloor/b\rfloor=\lfloor N/(ab)\rfloor\) for positive integers \(a,b\): both sides count how many complete blocks of \(ab\) fit in \(N\). Thus recursively dividing an existing quotient cannot create a new kind of state. The map using a second array is injective on the distinct large quotients: their producing indices are at most \(\lfloor\sqrt N\rfloor\), and different large quotient blocks have different right endpoints \(N/v\). This is a property of this state set, not of arbitrary integers \(v\).

2. Du Jiao sieve from a convolution identity

The idea in one line: if \(f\) is hard but \(f\) convolved with something easy is also easy, then the convolution identity gives \(F(N)\) in terms of \(F\) at smaller quotients.

Suppose \(h=f*g\) and the prefixes of \(h\) and \(g\) are cheap. We want \(F(N)=\sum_{n\le N}f(n)\). Start by summing the definition of convolution:

\[H(N)=\sum_{n\le N}\sum_{d\mid n}f(n/d)g(d).\]

Writing \(n=dk\) makes the meaning visible: for each possible \(d\), the allowed \(k\) run through \(1,\ldots,\lfloor N/d\rfloor\). Swapping those two sums gives

\[H(N)=\sum_{d\le N}g(d)F(\lfloor N/d\rfloor).\]

If \(g(1)=1\), the \(d=1\) term is exactly \(F(N)\); move every other term to the other side:

\[F(N)=H(N)-\sum_{d=2}^{N}g(d)F(\lfloor N/d\rfloor).\]

If instead \(g(1)\) is another unit, divide the whole equation by \(g(1)\) after isolating \(g(1)F(N)\); without an invertible \(g(1)\) this recurrence is not an algorithmic contract. Commutativity lets you swap the names of \(f,g\) if the other factor has easier prefix sums. The remaining formula appears to have \(N\) terms, but all indices \(\lfloor N/d\rfloor\) repeat. Group a block \(l\le d\le r\) with one quotient \(q\); its total coefficient is \(G(r)-G(l-1)\). That quotient grouping is the speedup, not the recurrence alone.

Mertens and totient prefixes

Let \(M(N)=\sum_{n\le N}\mu(n)\). The identity \(\mu*1=\varepsilon\) says that the convolution prefix \(H(N)\) is \(1\) for every \(N\ge1\). Here \(g=1\), so a block of indices \([l,r]\) has coefficient \(r-l+1\). Substitution gives

\[ M(N)=1-\sum_{l\in\mathcal B_N} (r_N(l)-l+1)M(\lfloor N/l\rfloor), \qquad r_N(l)=\left\lfloor\frac{N}{\lfloor N/l\rfloor}\right\rfloor. \]

Here \(\mathcal B_N\) is the set of quotient-block starts: begin with \(l=2\) and repeatedly replace \(l\) by \(r_N(l)+1\). It is not the set of every integer from \(2\) through \(N\).

Let \(\Phi(N)=\sum_{n\le N}\varphi(n)\). The identity \(\varphi*1=\operatorname{id}\) says its convolution prefix is \(1+2+\cdots+N=T(N)=N(N+1)/2\), giving

\[ \Phi(N)=T(N)-\sum_{l\in\mathcal B_N} (r_N(l)-l+1)\Phi(\lfloor N/l\rfloor), \]

with the same definitions of \(\mathcal B_N\) and \(r_N(l)\).

Precompute through \(B\ge\sqrt N\) and memoize only larger quotient states. Such a state is \(x=\lfloor N/k\rfloor\) for \(k\le N/B\). Its quotient loop takes \(O(\sqrt x)\) operations, so all memoized work is at most

\[ O\left(\sum_{k\le N/B}\sqrt{N/k}\right) =O\left(\sqrt N\sqrt{N/B}\right) =O(N/\sqrt B). \]

The middle bound follows by comparing \(\sum_{k\le K}k^{-1/2}\) with its integral, which is at most \(2\sqrt K\) up to a constant. Total time is \(O(B+N/\sqrt B)\) and storage is \(O(B+N/B)\), assuming \(O(1)\) prefix access and memo lookup. Choosing \(B\) near \(N^{2/3}\) balances the terms and gives \(O(N^{2/3})\) time and space for one query. This bound does not automatically amortize across unrelated query bounds.

Worked recurrence. For \(N=6\), \(\mu(1),\ldots,\mu(6)\) are \(1,-1,-1,0,-1,1\). The block formula uses \([2,2],[3,3],[4,6]\): \(M(6)=1-M(3)-M(2)-3M(1)=1-(-1)-0-3=-1\). The corresponding totient formula gives \(\Phi(6)=21-\Phi(3)-\Phi(2)-3\Phi(1)=21-4-2-3=12\). The weights are lengths of blocks, not numbers of distinct quotient values.

The quadratic scale of \(\sum\varphi(n)\) requires wide intermediates. Reduce modulo the problem modulus inside every operation if that is what the statement asks.

Derivation workflow

  1. Name the wanted prefix \(F\).
  2. Find \(g\) so \(h=f*g\) has an elementary prefix.
  3. Sum \(h(n)\) for \(n≤N\), swap \(n=dk\), and isolate \(F(N)\).
  4. Express coefficient sums on \([l,r]\) with prefix formulas.
  5. Confirm every recursive argument is \(\lfloor N/l\rfloor\) and smaller than \(N\).

3. Prime-sum sieve: the engine inside Min_25

Min_25 first solves a narrower problem: quickly find sums over primes, such as \(\sum_{p\le w}p^k\), at every quotient state \(w=\lfloor N/l\rfloor\). Initialize

\[g_k(w)=\sum_{i=2}^{w}i^{k}.\]

At the start, \(g_k(w)\) is the sum over all integers \(2,\ldots,w\). Process primes \(p\) in increasing order. At the \(p\) stage, subtract the composites whose smallest prime factor is \(p\); for every state \(w\ge p^2\) this is

\[g_k(w)\mathrel{-}=p^{k}\left(g_k(\lfloor w/p\rfloor)-S_k(p-1)\right),\]

where \(S_k(p-1)=\sum_{q<p,q prime}q^{k}\). After processing all \(p≤\sqrt{N}\), \(g_k(w)=\sum_{q≤w,q prime}q^{k}\).

Why \(p^2\)? Any composite first removed at this stage has least prime factor \(p\), hence it is \(p\cdot x\) with \(x\ge p\). Just before the \(p\) stage, \(g_k(\lfloor w/p\rfloor)\) consists of two kinds of surviving entries: primes below \(p\), which are deliberately retained as final prime answers, and integers having no prime factor below \(p\). Only the second kind can be a valid cofactor \(x\), so \(S_k(p-1)\) removes the retained small primes. Updating states in descending order prevents the right side from using values already modified by the current prime. After all relevant stages, only prime contributions remain.

Worked sieve. For \(k=0,N=10\), initially \(g_0(10)=9\), counting \(2,\ldots,10\). The \(p=2\) update removes \(4,6,8,10\), leaving five entries. The \(p=3\) update removes \(9\), leaving the four primes \(2,3,5,7\). At \(w=5\), processing prime two before \(w=10\) would change the cofactor data used by larger states; descending order is what preserves the stage invariant.

For \(k=0\) this computes \(\pi(w)\), the number of primes at most \(w\). One array uses \(O(\sqrt N)\) space. An elementary upper bound on update count is \(O(N^{3/4})\): primes at most \(N^{1/4}\) have at most \(2\sqrt N\) states each, while larger primes can update only \(O(N/p^2)\) large states; \(N\sum_{j>N^{1/4}}j^{-2}=O(N^{3/4})\). Using prime-density estimates sharpens this to \(O(N^{3/4}/\log N)\) asymptotically for this prime-sum core, as discussed in the official ABC370 editorial. The simple bound already explains why the prime-sum stage is sublinear.

4. Full Min_25 sieve

Min_25 extends that prime-sum engine to a multiplicative function. Assume \(f\) is multiplicative, each \(f(p^{e})\) is computable in \(O(1)\), and the prime values, not necessarily all prime-power values, satisfy

\[f(p)=\sum_{k=0}^{K}c_kp^{k}\]

for small fixed \(K\). Run the prime-sum sieve for each required power \(k\); combine the arrays to obtain

\[G_f(x)=\sum_{p\le x}f(p).\]

The prime-sum sieve gives the contribution of prime numbers. To cover every composite exactly once, enumerate it by its least prime and the exact exponent of that prime. Index primes from \(p_0=2\) and set \(G_f(p_{-1})=0\). Define \(S(x,y)\) as the sum of \(f(n)\) for \(2\le n\le x\) whose least prime is at least \(p_y\). Calls maintain \(p_{y-1}\le x\) (with the \(y=0\) sentinel understood), so its prime-only base contribution is \(G_f(x)-G_f(p_{y-1})\) and is zero when the interval contains no prime. For every possible least prime \(p_i\), enumerate an exponent \(e\ge1\). The term with \(S\) counts numbers \(p_i^e m\) where \(m>1\) has no prime factor at most \(p_i\); the separate term counts pure powers (the prime \(p_i\) itself is already in the base term):

\[ S(x,y)=G_f(x)-G_f(p_{y-1})+ \sum_{\substack{i\ge y\\p_i^2\le x}} \sum_{\substack{e\ge1\\p_i^{e+1}\le x}} \left(f(p_i^e)S(\lfloor x/p_i^e\rfloor,i+1)+f(p_i^{e+1})\right). \]

Finally \(f(1)+S(N,0)=1+S(N,0)\) is the prefix, using the standard convention for a multiplicative function. The shift in the pure-power exponent is deliberate: as \(e=1,2,\ldots\), those terms list \(p_i^2,p_i^3,\ldots\) exactly once, while the cofactor term uses \(p_i^e\) as the exact valuation. The condition \(p_i^{e+1}\le x\) also safely ends the cofactor branch: any permitted nontrivial cofactor is at least \(p_{i+1}>p_i\). This decomposition is unique.

As a hand check, take \(f(n)=1\) and \(x=10\). The base term counts the four primes \(2,3,5,7\). The branch for least prime \(2\) contributes \(6,10\) from \(2\cdot\{3,5\}\) and the pure powers \(4,8\); the branch for least prime \(3\) contributes the pure power \(9\). Together with \(f(1)\) these are all ten integers, each assigned to exactly one least-prime branch.

Keep the enumeration cost separate from the prime-sum cost. Let \(E(N)\) be the number of \((i,e)\) branches actually visited by the displayed recursion from \((N,0)\). With \(O(1)\) local values and prime-prefix access, the cost is \(O((K+1)N^{3/4}+E(N))\) by the elementary prime-stage bound, with \(O((K+1)\sqrt N+\log N)\) storage for arrays and a depth-first stack. The logarithmic stack bound follows because each recursive step divides by at least two. A conservative \(E(N)=O(N)\) bound follows by assigning each call its product of selected prime powers: the strictly increasing prime indices give a unique factorization path for every product, and all products are at most \(N\). Practical enumeration is much smaller on common instances, but this is not a proof that every variant inherits the prime-sum bound. Count these branches when benchmarking the chosen library; optimized Min_25 variants require their own complexity analysis.

Applicability signals. \(N\) is around \(10^{9}–10^{12}\), the statement gives a multiplicative function through its prime powers, and its value at a prime is polynomial (examples: \(\varphi(p)=p-1\), \(\mu(p)=-1\), \(\sigma_k(p)=1+p^{k}\)).

Non-applicable cases. If \(f(p)\) depends on an arbitrary property of \(p\) for which no fast prime prefix exists, standard Min_25 has no base data. If only \(\mu/\varphi\) prefixes are needed, Du Jiao is simpler.

5. Powerful-number support

The third strategy attacks the problem from the opposite direction: instead of finding a convolution partner that simplifies the sum, find one that makes almost all of the terms vanish.

A positive integer is powerful if every prime dividing it has exponent at least two. For example, \(72=2^3\cdot3^2\) is powerful whereas \(12=2^2\cdot3\) is not. The count through \(N\) is \(O(\sqrt N)\) because every powerful integer has the unique representation

\[n=a^2b^3,\qquad b\text{ square-free}.\]

For each prime exponent \(e\ge2\), choose the unique \(e=2u+3v\) with \(v\in\{0,1\}\); the primes with \(v=1\) form \(b\). Consequently \(b\le N^{1/3}\) and \(a\le\sqrt{N/b^3}\). Summing over \(b\) gives \(\sqrt N\sum_b b^{-3/2}=O(\sqrt N)\) candidates. The requirement that \(b\) be square-free is what makes the representation unique.

This sparsity yields another generic strategy. Choose an easy multiplicative \(g\) agreeing with \(f\) on primes, and define

\[h=f*g^{-1}\quad\Longleftrightarrow\quad f=h*g.\]

Because multiplicative functions have value \(1\) at \(1\), the prime-power convolution identity gives \(h(p)=f(p)-g(p)=0\). Multiplicativity then forces \(h(n)=0\) whenever any prime has exponent exactly one: its product over prime-power factors contains \(h(p)=0\). Thus \(h\) is supported on powerful numbers. Let \(G(x)=\sum_{n\le x}g(n)\). In the convolution \(f=h*g\), choosing a divisor \(d\) for the \(h\) factor leaves a \(g\) factor through \(\lfloor N/d\rfloor\); summing those choices gives

\[F(N)=\sum_{d\le N\atop d\text{ powerful}}h(d)G(\lfloor N/d\rfloor).\]

Compute local prime-power coefficients from

\[f(p^{e})=\sum_{j=0}^{e}h(p^{j})g(p^{e-j}),\]

so \(h(1)=1\), \(h(p)=0\), and for \(e≥2\),

\[h(p^{e})=f(p^{e})-\sum_{j=0}^{e-1}h(p^{j})g(p^{e-j}).\]

Enumerate powerful numbers by DFS over increasing primes, choosing exponent zero or at least two; accumulate \(h(d)G(N/d)\). Prune when \(d·p²>N\). Alternatively enumerate the unique \(a²b³\) representation when the coefficient is easier to recover that way.

This method is attractive when \(G(x)\) is elementary or already available and \(h(p^{e})\) is cheap. Complexity is commonly around \(O(\sqrt{N} \operatorname{polylog} N)\) plus the cost of obtaining \(G\) and primes, but must be derived for the exact enumeration.

A common special case: perfect powers

To count integers \(n>1\) representable as \(a^{b}\) with \(a,b>1\), enumerate exponents but remove duplicate representations. If \(n=\prod_i p_i^{e_i}\), its maximal possible exponent is \(\gcd_i e_i\); thus \(n\) is a nontrivial perfect power exactly when this gcd exceeds one. Möbius inversion over exponents, or counting by the maximal exponent, avoids double counting. Integer kth roots must be corrected with exact 128-bit power comparisons—floating- point pow alone is unsafe near \(10^{18}\).

Worked powerful-support transformation

Let \(f(n)=\tau(n)\) and \(g(n)=2^{\omega(n)}\), where \(\omega(n)\) counts distinct prime factors. Both functions equal two at a prime. At \(p^e\), \(g(p^e)=2\) for \(e\ge1\). Local convolution gives \(h(p)=0\), \(h(p^2)=3-2=1\), and \(h(p^3)=4-(2+0+2)=0\). Continuing gives \(h(p^{2j})=1\) and \(h(p^{2j+1})=0\): the local generating-series quotient is

\[ \frac{\sum_{e\ge0}(e+1)t^e}{1+2t+2t^2+\cdots} =\frac{1/(1-t)^2}{(1+t)/(1-t)} =\frac1{1-t^2}. \]

These are formal identities with constant-one denominators, valid over the integers without dividing coefficients. Thus \(h\) is the indicator of squares, and

\[\sum_{n\le N}\tau(n)=\sum_{a\le\sqrt N}G(\lfloor N/a^2\rfloor).\]

This is an identity, not automatically a fast algorithm: we still need cheap \(G\). Matching on primes makes support sparse but does not supply that prefix. For \(N=4\), \(G(4)=1+2+2+2=7\) and \(G(1)=1\), giving \(8\).

6. Choosing a method

Signal First choice Reason
known simple \(f*g=h\) Du Jiao shortest recurrence, quotient memoization
polynomial \(f(p)\) and arbitrary manageable \(f(p^{e})\) Min_25 sieves prime contributions then enumerates least primes
can match \(f(p)\) with an easy \(g\); differences begin at \(p²\) powerful-number sieve transformed support is sparse
only prime count/sums are wanted prime-sum core no full multiplicative DFS needed

Pitfalls

  • Prove the convolution identity before optimizing it; a swapped divisor argument silently computes the wrong function.
  • In prime-sum DP, process \(w\) descending and only while \(w≥p²\).
  • Distinguish “primes \(<p\)” from “primes \(≤p\)” in the base subtraction.
  • Min_25 recursion must enforce strictly increasing prime factors after choosing the least prime.
  • Include \(f(1)\) exactly once.
  • Use 128-bit arithmetic for \(p²\), prime-power growth, polynomial sums, and unmodded answers.
  • Modular polynomial sums may require division by \(2,6,…\); use integer formulas before reduction if the modulus is not guaranteed coprime to denominators.
  • Cached values keyed by the actual argument \(x\) may be reused across queries for the same function and coefficient ring. Array slots keyed by \(N/x\) are query-specific and must be rebuilt when \(N\) changes.

Ordered practice

1. Relatively Prime Powers — Codeforces 1036F

  • Level: Mastery · Language: English/Russian
  • Trains: perfect-power counting, Möbius inversion over exponents, exact integer roots.
  • Editorial: official Educational Round 50 editorial
Hint 1 Count numbers that are not expressible as a nontrivial perfect power, then complement.
Hint 2 A number may appear under several exponents; classify it by the gcd of exponents in its prime factorization.
Hint 3 Use Möbius inclusion–exclusion on exponents and exact corrected kth roots up to the relevant logarithm.
TipEditorial guidance: many queries

The exponent-inversion formula derives the answer, but the official task has many queries. Precompute all non-square perfect powers through the maximum query: enumerate bases for odd exponents \(3,5,\ldots,\lfloor\log_2 X\rfloor\), discard squares using exact integer square roots, then sort and deduplicate. Every non-square perfect power has an odd exponent at least three in some representation. The largest base range is the cube range, \(X^{1/3}\); the total candidates are \(O(X^{1/3}\log X)\) by a conservative bound. For each query \(n\), squares contribute \(\lfloor\sqrt n\rfloor-1\) and a binary search counts precomputed non-squares. The elegant count is \(n-\lfloor\sqrt n\rfloor-C(n)\). Exact roots and deduplication matter: \(64\) has several representations but is removed as a square.

Exercises with solutions

1. Blocks and boundary cases — concept check

List the quotient blocks for \(N=10\), then compute \(M(10)\) from smaller Mertens prefixes.

TipHint and solution

Starting at two, the blocks are \([2,2],[3,3],[4,5],[6,10]\), with quotients \(5,3,2,1\). Since \(M(5)=-2,M(3)=-1,M(2)=0,M(1)=1\), \(M(10)=1-(-2)-(-1)-2\cdot0-5=-1\). At \(N=1\) there are no blocks and \(M(1)=1\).

2. A weighted recurrence — derivation

Let \(f(n)=n^2\varphi(n)\). Find a convolution with an elementary prefix, and write the grouped recurrence for \(F(N)\).

TipHint and solution

Take \(g(n)=n^2\). Then \((f*g)(n)=\sum_{d\mid n}d^2\varphi(d)(n/d)^2 =n^2\sum_{d\mid n}\varphi(d)=n^3\). Thus \(F(N)=\sum_{n\le N}n^3- \sum_{[l,r],\,l\ge2}(\sum_{d=l}^r d^2)F(\lfloor N/l\rfloor)\). Here \(\sum_{n\le N}n^3=[N(N+1)/2]^2\); square sums provide block weights. At \(N=3\), \(F(3)=1+4+18=23=36-4-9\). All fractions in power-sum formulas are exact integer divisions if the answer modulus does not permit the corresponding inverses.

3. Perfect powers without duplicates — synthesis

Count the integers \(2\le n\le X\) that are nontrivial perfect powers, using exact integer roots and Möbius values of exponents.

TipHint and solution

If the gcd of the prime exponents of \(n\) is \(g\), then \(n\) is an \(e\)th power iff \(e\mid g\). The weight \(-\sum_{e\mid g,\,e\ge2}\mu(e)\) is zero when \(g=1\) and one otherwise. Summing by \(e\) gives

\[-\sum_{e=2}^{\lfloor\log_2 X\rfloor} \mu(e)\left(\lfloor X^{1/e}\rfloor-1\right).\]

Subtract one to exclude base one. At \(X=16\), the terms are \(3+1+0=4\), representing \(4,8,9,16\). Each root may be found by binary search with capped integer powers; one safe baseline uses \(O(\log X\log\log X)\) arithmetic operations per root and \(O(\log X)\) roots. A faster integer-root library must still correct rounding exactly.

Summary and reference sheet

The closed state set is \(\{\lfloor N/i\rfloor:1\le i\le N\}\). Du Jiao isolates a prefix from \(h=f*g\) when \(g(1)\) is a unit and the other prefixes are cheap; one-query cost is \(O(B+N/\sqrt B)\) for \(B\ge\sqrt N\). Prime-sum sieving removes composites at their unique least-prime stage and updates quotient values downward. Full multiplicative enumeration additionally chooses the exact least-prime exponent; its branch count is a separate cost. Matching functions on primes confines their convolution quotient to powerful numbers, but a cheap prefix for the matched function remains essential. Every method must include the value at one exactly once.
