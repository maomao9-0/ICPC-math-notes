05 — Group Actions, Burnside, and Pólya

Why you cannot just divide by the symmetries

Count the ways to color three beads of a circular necklace black or white, where rotating the necklace does not create a new necklace.

There are \(2^3 = 8\) colored strings and \(3\) rotations, so the answer is \(8/3\). Which is not an integer, so something is wrong.

The mistake is assuming every necklace is counted the same number of times. BBB looks identical under all three rotations — it is counted once. BBW gives three distinct strings — it is counted three times. Dividing by \(3\) treats these the same, and it does not work.

The fix is a beautiful one: instead of averaging over objects, average over moves. For each rotation, count how many colorings it leaves unchanged, and take the mean. Here: the identity fixes all \(8\), and each of the two genuine rotations fixes only the \(2\) constant colorings, so

\[\frac{8 + 2 + 2}{3} = 4.\]

And indeed there are four: all-black, all-white, one black, one white. This chapter explains why that trick is not a coincidence, and how to use it when the objects being colored carry constraints of their own.

Prerequisites and learning objectives

Use bijections and double counting, inclusion–exclusion, and modular units. Weighted inventories use coefficient extraction, introduced locally below.

You should finish able to write down the exact symmetry group for a problem, prove the averaging rule instead of trusting it, derive the cycles of a move on positions, count constrained fixed objects, and say precisely when dividing by \(|G|\) is legal in a modular ring.

All sets and groups here are finite. The notation \(X/G\) means the set of orbits, not division. A permutation is a bijection of positions; its cycles are the loops you traverse by applying it repeatedly, and distinct cycles share no position.

1. From “the same up to a move” to a group action

A finite group \(G\) is a set of allowed moves with an associative composition, an identity move, and an inverse for each move. It acts on a set \(X\) of objects when each \(g \in G\) gives a map \(x \mapsto g \cdot x\), the identity fixes everything, and \(g\cdot(h\cdot x) = (gh)\cdot x\) — that last law just says composing moves and multiplying in the group agree.

Two objects are “the same” when a move carries one to the other. The equivalence class is the orbit \(Gx\): every version of \(x\) reachable by allowed moves. One orbit = one object up to symmetry, so the quantity a problem asks for is \(|X/G|\).

The stabilizer \(G_x\) is the set of moves that leave \(x\) unchanged. The first theorem ties the two together:

\[|Gx|\cdot|G_x| = |G|. \tag{1}\]

Proof. Send each move \(g\) to the object \(g \cdot x\); the image is exactly the orbit. If \(h \cdot x = y\), then the moves landing on \(y\) are precisely the products \(hs\) with \(s \in G_x\) — every such product works, and conversely \(g\cdot x = h \cdot x\) forces \(h^{-1}g \in G_x\). So every orbit element has exactly \(|G_x|\) preimages, and the \(|G|\) moves split into \(|Gx|\) equal groups. (Those groups are called cosets of the stabilizer.) \(\square\)

Equation (1) is exactly the reason naive division fails. For the three-bead necklace, BBB has \(|G_x| = 3\) and orbit size \(1\), while BBW has \(|G_x| = 1\) and orbit size \(3\). Orbits have different sizes, so no single divisor can fix the count.

Recognition — write the move set first. Everything downstream depends on getting this right:

  • necklaces: rotations, the cyclic group \(C_n\), size \(n\);
  • bracelets (you may flip them over): rotations and reflections, the dihedral group \(D_n\), size \(2n\);
  • a square grid under quarter turns: a small geometric permutation group;
  • interchangeable colors: a second action, usually handled by cycle types or by another layer of Burnside.

And check one thing: the moves must preserve validity. If a move can turn a valid object into an invalid one, its orbits are not the equivalence classes the problem is asking about.

2. Burnside’s lemma

Let \(\operatorname{Fix}(g) = \{x : g\cdot x = x\}\). Burnside’s lemma (also Cauchy–Frobenius) states

\[|X/G| = \frac{1}{|G|}\sum_{g \in G}\left|\operatorname{Fix}(g)\right|. \tag{2}\]

It is startling at first because the summand is a different count for every move, and nothing in it obviously refers to orbits.

Proof by double counting. Count the pairs \((g,x)\) with \(g \cdot x = x\). Grouping by \(g\) gives the right-hand numerator. Grouping by orbit instead: in an orbit \(O\), equation (1) says each object has \(|G|/|O|\) fixing moves, so the orbit contributes

\[|O| \cdot \frac{|G|}{|O|} = |G|\]

pairs — the same total for every orbit, large or small. So the numerator is \(|G|\) times the number of orbits. \(\square\)

That is the real content: the averaging exactly compensates for uneven orbit sizes, because a small orbit is made of objects with correspondingly large stabilizers.

The coloring special case. If \(X\) is all colorings of \(v\) positions with \(c\) named colors, a move \(g\) permutes the positions into cycles. A coloring fixed by \(g\) must be constant along each cycle, and each cycle chooses its color independently, so

\[|\operatorname{Fix}(g)| = c^{z(g)}, \quad z(g) = \#\text{cycles of } g.\]

Almost every Burnside computation reduces to counting cycles.

Necklaces, worked out

Rotation by \(r\) on \(n\) positions jumps by \(r\) each step and first returns after \(n/\gcd(n,r)\) steps, so it has \(\gcd(n,r)\) cycles. Then (2) gives

\[ N(n,c) = \frac1n\sum_{r=0}^{n-1}c^{\gcd(n,r)} = \frac1n\sum_{d \mid n}\varphi(n/d)\,c^{d}. \tag{3} \]

The second form groups rotations by their cycle count, which is what you actually want after factoring \(n\): writing \(r = du\) and \(n = dv\) for the rotations with \(\gcd(n,r) = d\) gives \(0 \le u < v\) with \(\gcd(u,v) = 1\), i.e. exactly \(\varphi(v) = \varphi(n/d)\) of them. (The identity is \(d = n\) with \(\varphi(1) = 1\).)

At \(n = 3\), \(c = 2\) this reproduces the opening computation: \((8+2+2)/3 = 4\).

Bracelets need their own cycle analysis. Reflections must be examined by parity of \(n\), which is why a memorized necklace formula cannot answer a bracelet question:

  • \(n\) odd: every reflection axis passes through one position and pairs up the rest — \(1 + (n-1)/2\) cycles.
  • \(n\) even: half the axes pass through two positions (\(2 + (n-2)/2\) cycles) and half pass between positions (\(n/2\) cycles).

At \(n = 4\), \(c = 2\): rotations give \(16 + 2 + 4 + 2 = 24\), the two vertex-axis reflections give \(2^3\) each and the two edge-axis reflections \(2^2\) each, another \(24\). So bracelets \(= 48/8 = 6\) and necklaces \(= 24/4 = 6\) — equal here, by coincidence. At \(n = 6\), \(c = 2\): rotations sum to \(84\) (\(14\) necklaces), reflections add \(3\cdot 16 + 3 \cdot 8 = 72\), giving \(156/12 = 13\) bracelets. The two counts differ as soon as some necklace is not its own mirror image.

NoteNon-faithful actions are fine

For \(n = 1, 2\) several formal dihedral moves induce the same permutation of positions. We still sum over all \(2n\) formal group elements. Burnside holds regardless: each distinct induced permutation simply appears the same number of times, top and bottom.

3. Pólya: keeping track of how many of each color

Burnside with \(c^{z(g)}\) answers “how many necklaces”, but not “how many necklaces with exactly three red and two blue beads”. To keep the inventory, attach a marker variable \(y_i\) to color \(i\), and let a cycle of length \(j\) painted color \(i\) contribute \(y_i^{\,j}\) — because that single choice uses color \(i\) exactly \(j\) times.

Record the cycle structure of the whole group in the cycle index

\[Z_G(s_1, s_2, \ldots) = \frac1{|G|}\sum_{g \in G}\prod_{j \ge 1}s_j^{\,c_j(g)}, \tag{4}\]

where \(c_j(g)\) is the number of length-\(j\) cycles of \(g\). Substituting

\[s_j \leftarrow y_1^{\,j} + \cdots + y_c^{\,j}\]

makes the coefficient of \(y_1^{a_1}\cdots y_c^{a_c}\) equal to the number of symmetry classes using exactly \(a_i\) positions of color \(i\). Setting every \(y_i = 1\) recovers plain Burnside, since each \(s_j\) becomes \(c\).

Smallest possible example. Two positions, group = {identity, swap}. The identity has two \(1\)-cycles and the swap has one \(2\)-cycle, so \(Z = \tfrac12(s_1^2 + s_2)\), which substitutes to

\[\tfrac12\left((y_1+y_2)^2 + y_1^2 + y_2^2\right).\]

The coefficient of \(y_1y_2\) is \(\tfrac12(2 + 0) = 1\): the two mixed colorings form a single class. Note why the swap contributed nothing there — it fixes no mixed coloring, which is precisely why its term is \(y_1^2 + y_2^2\) and not \((y_1+y_2)^2\).

Weighted states. If each position may hold a state of some nonnegative integer weight, with inventory \(A(x) = \sum_w a_w x^w\) (\(a_w\) finite, counting available states of weight \(w\)), substitute \(s_j \leftarrow A(x^j)\): a cycle of length \(j\) repeats its chosen state \(j\) times, multiplying the weight by \(j\). Then \([x^s]\) selects total weight \(s\). For instance a swapped pair of positions holding positive integers has inventory \(x^2 + x^4 + \cdots = x^2/(1-x^2)\), since both positions must hold the same value. Truncate everything at the requested total weight.

4. Constraints go inside the fixed-point count

This is where most Burnside solutions go wrong. Burnside is only the outer average; the inner count must already respect the problem’s constraints. The procedure per group element is:

  1. find its cycles on the atomic positions;
  2. contract each cycle to a single node — a fixed object is constant on it;
  3. count the valid assignments to the contracted structure;
  4. add that to the numerator.

Contraction can change the structure in ways that matter. If an edge’s two endpoints collapse into one node, that self-loop makes a proper coloring impossible — the fixed count is zero. Contraction may also create parallel edges, usually harmless for proper colorings but relevant for weights.

Worked example: proper colorings of a triangle

Count proper \(3\)-colorings of a triangle up to rotation.

The identity fixes \(3 \cdot 2 \cdot 1 = 6\). Each nonidentity rotation contracts all three vertices into one node, turning every edge into a self-loop, so it fixes \(0\) proper colorings. Burnside gives

\[\frac{6 + 0 + 0}{3} = 2,\]

the two cyclic orders of the three colors.

Using the unrestricted formula \(c^{z(g)}\) instead would give \((27 + 3 + 3)/3 = 11\) — a count of all colorings up to rotation, proper or not. The constraint must live inside each term, never be applied after averaging.

5. Symmetric groups: sum over cycle types, not permutations

When the group is \(S_n\) (say, all relabellings of \(n\) vertices), summing over \(n!\) elements is hopeless. But if the fixed count depends only on the cycle lengths — which it does whenever the action is built from positions — then all permutations of the same cycle type contribute equally, and you can sum over the integer partitions of \(n\) instead.

A type \(1^{m_1}2^{m_2}\cdots\) with \(\sum_i i\,m_i = n\) contains

\[\frac{n!}{\prod_i i^{m_i}m_i!} \tag{5}\]

permutations. The denominator has a concrete meaning: start from all \(n!\) linear orderings cut into cycles of the prescribed lengths, then quotient by rotating each cycle of length \(i\) (\(i^{m_i}\)) and by reordering the \(m_i\) cycles of equal length (\(m_i!\)). Relatedly, two permutations are conjugate (\(g \mapsto hgh^{-1}\)) exactly when they share a cycle type, since conjugation only renames entries.

If the objects carry both vertex colors and edges, there are two induced actions to handle: a fixed coloring is constant on each vertex cycle, while a fixed edge set is constant on each unordered-pair cycle. Requirements like “every color is used” go inside that fixed count, typically by inclusion–exclusion over the missing colors.

Induced cycles on pairs, derived

A vertex permutation with cycles of lengths \(a_1, \ldots, a_r\) acts on unordered vertex pairs. Two cases:

  • Pairs across two cycles of lengths \(a, b\): a pair returns to itself after \(\operatorname{lcm}(a,b)\) steps, and there are \(ab\) such pairs, giving \(ab/\operatorname{lcm}(a,b) = \gcd(a,b)\) pair cycles.
  • Pairs inside one cycle of length \(a\): classify by circular distance \(1, \ldots, \lfloor a/2\rfloor\); each distance forms one orbit (the opposite-pair class, when \(a\) is even, has size \(a/2\) rather than \(a\)).

So the number of induced pair cycles is

\[e = \sum_{i=1}^{r}\left\lfloor \frac{a_i}{2}\right\rfloor + \sum_{1 \le i < j \le r}\gcd(a_i, a_j),\]

and a fixed simple graph independently includes or excludes each whole pair cycle: \(2^e\) of them.

Check on three vertices. Type \((2,1)\) gives \(e = 1 + 1 = 2\): the edge inside the swapped pair is a cycle by itself, and the two edges to the fixed vertex form one orbit — \(4\) invariant graphs. Over all of \(S_3\) the three types contribute \(1\cdot 8 + 3 \cdot 4 + 2 \cdot 2 = 24\), so there are \(24/6 = 4\) unlabelled simple graphs on three vertices: with zero, one, two, or three edges. Correct.

6. Arithmetic and modelling checks

  • Dividing by \(|G|\) modulo a prime \(p\) requires \(p \nmid |G|\). Otherwise divide exactly over the integers first, or rearrange (see Section 7).
  • A reflection and a rotation of the same order need not have the same cycle structure — derive cycles, do not guess them.
  • If the colors are also interchangeable, position-Burnside alone still treats color names as distinct; you need to model the color symmetry too.
  • Exact multiplicities need coefficient extraction from (4), not \(c^{\,\text{cycles}}\).
  • Before coding: take a \(2\)- or \(3\)-position toy case, enumerate raw objects, group the orbits by hand, and compare against your Burnside numerator.

7. Costs, the division trick, and a reference table

For an explicitly listed group acting on \(v\) positions, cycle decomposition costs \(O(v)\) per element, so \(O(|G|v)\) plus the fixed-object counting. Necklace divisor grouping costs one modular exponentiation per divisor after factoring \(n\). Summing over the cycle types of \(S_n\) visits the integer partitions of \(n\), with the edge-cycle formula costing \(O(n^2)\) gcds per type — useful in practice, but partition enumeration is itself the limiting factor, not a polynomial-time algorithm.

TipDividing by \(|G|\) when it is not a unit

The Burnside numerator \(A\) is always divisible by \(g = |G|\) as an integer, even when \(g\) is \(0\) modulo the requested modulus \(m\). Compute \(A \bmod gm\) instead: writing \(A = qgm + r\) with \(0 \le r < gm\), divisibility gives \(g \mid r\) and

\[\frac Ag \equiv \frac rg \pmod m .\]

This needs your fixed-count algorithm to run modulo \(gm\) and that modulus to fit your arithmetic model, but it avoids an inverse that does not exist.

Before implementing, name five things: the positions, the moves, what makes an object valid, what a cycle constraint forces, and the ring in which the final division happens. Then test a case with a nontrivial stabilizer.
